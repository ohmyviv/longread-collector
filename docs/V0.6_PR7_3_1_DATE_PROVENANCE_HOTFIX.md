# v0.6 PR-7.3.1 — L4 Date Provenance Hotfix

## Why this hotfix exists

PR-7.3 merged the L4 publication/source evidence model and restarted natural-shadow acceptance at Day 0. The first post-merge scheduled run,
`COL-20260809-230000-BJT-intl_early`, passed the full-parallel engineering invariants but failed publication-date correctness.

The failures were not a new L5/L6 policy issue. They showed that structured publication evidence already produced by frozen v0.5.6m was being flattened before the v0.6 L4 resolver could use its provenance model.

## Natural-run evidence

### C&EN false stale dates

Two acquired C&EN articles exposed the same failure mode:

- `How snails use chemistry to modify their mucus materials`
  - article header: `August 7, 2026`
  - legacy `body_header_standalone_date`: Related-card `August 7, 2025`
- `Why Nigeria’s antibiotic leads stall at the lab bench`
  - article header: `August 6, 2026`
  - legacy `body_header_standalone_date`: Related-card `August 5, 2024`

The legacy standalone-date extractor searches a 6000-character body window. On these pages a standalone date in a Related card was therefore promoted as high-confidence body-header evidence and overwrote the top-level article date.

The same post-extraction freshness payload still retained the correct independent `page_metadata_published` candidate. That evidence did not survive into the PR-7.3 shared L4 surface with its provenance intact.

### Same-day URL/page metadata over-demotion

The New Humanitarian and similar pages supplied:

- a weak URL-derived date, and
- an independent page-metadata publication timestamp on the same calendar day.

PR-7.3 correctly demoted the URL fact, but the compatibility bridge represented dates mainly as flattened strings. URL-projection cleanup could therefore remove the independent page date because the normalized calendar value was identical, leaving an unnecessary `publication_date_unknown_defer`.

## Root cause

Two bridge behaviors combined:

1. `LegacyV056mAdapter` projected publication dates primarily into `AcquisitionBundle.raw_dates`, losing the source/role/confidence fields already present in `article.metadata["freshness"]["evidence"]`.
2. `share_control_acquisition` replaced the control bundle's evidence with only a `shared_control_acquisition` body-hash marker.

L4 therefore could not reliably distinguish page metadata, body heuristics, discovery metadata, and URL evidence even though frozen v0.5.6m had already recorded those distinctions.

## PR-7.3.1 design

### Preserve structured legacy publication evidence

`v06/legacy/adapter_v0731.py` wraps the frozen compatibility adapter and adds immutable `legacy_publication_date_candidate` evidence rows to the acquisition bundle. The rows preserve:

- value
- source
- role
- confidence
- priority
- raw observation

The frozen v0.5.6m pipeline is not modified.

### Preserve factual evidence across the zero-request share

`share_control_acquisition` continues to remove control attempts, latency, and cost from the shadow bundle so network metrics cannot be double-counted. It now preserves factual control evidence on the shared bundle and appends the body fingerprint marker.

The shadow Acquisition `StageEvent` still contains only the zero-request share marker. Shadow request count, Firecrawl request count, and incremental cost therefore remain zero by construction.

### Resolve structured candidates in L4

`publication_v0731.py` keeps the PR-7.3 semantic and precedence rules but adds explicit mapping from preserved legacy sources to v0.6 provenance:

- page metadata -> `page_metadata`
- feed/discovery evidence -> `discovery_metadata`
- URL evidence -> `url_path` and contextual-only
- verified body-header evidence -> `article_local_metadata`
- other preserved acquisition observations -> `acquisition_metadata`

A generic `raw_dates` candidate is omitted when the same normalized value is already represented by structured evidence, because it is only a flattened duplicate and would otherwise create artificial conflicts.

### Calibrate only the proven legacy heuristic

`body_header_standalone_date` remains available as evidence. It is treated as article-local only when its raw date actually occurs in a tight title-adjacent header window. If the occurrence is outside that window, it is retained as low-confidence acquisition evidence rather than discarded.

This rule is intentionally limited to the heuristic proven unsafe by the natural run. Other article-local evidence and the PR-7.3 same-semantic conflict rule remain unchanged.

## Frozen boundaries

PR-7.3.1 does not change:

- PR-7.2 L5 Editorial Judge semantics or version;
- L6 freshness/portfolio policy;
- source-relationship rules;
- Discovery or Acquisition Gate behavior;
- acquisition network behavior or budgets;
- legacy v0.5.6m control behavior;
- PR-8/canary scope.

## Regression requirements

The hotfix must keep all existing PR-7.3 tests and add coverage proving:

1. C&EN Related-card standalone dates no longer outrank independent page publication metadata.
2. An independent page-metadata date survives URL-date demotion even when both normalize to the same calendar day.
3. Structured legacy publication evidence survives both the compatibility adapter and the shared-acquisition boundary.
4. URL-only publication evidence remains contextual and cannot establish `published_at`.
5. Genuine same-semantic article-local conflicts remain explicit with the PR-7.3 confidence cap.
6. L5 stays frozen at `editorial-judge-v0.6-pr7.2`.

## Acceptance semantics

The 2026-08-09 `intl_early` run is a failed acceptance attempt and does not count as Day 1. Acceptance remains at Day 0.

After PR-7.3.1 is merged, counting restarts from the first subsequent scheduled natural shadow that passes both engineering invariants and semantic review. Manual replays are regression evidence, not acceptance days.
