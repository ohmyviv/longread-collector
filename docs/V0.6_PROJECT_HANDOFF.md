## 2. Settled target architecture

```text
Source Registry
      ↓
GitHub Collector
  ├─ L1 Discovery
  ├─ L2 Acquisition Gate
  ├─ L3 Acquisition
  └─ raw observations / replayable snapshots
      ↓
L4 Canonical Article
      ↓
L5 Editorial Judge
      ↓
Candidate Universe
      ↓
L6 Policy / Portfolio Selection
      ↓
history / archive / delivery
```

Responsibilities remain strict:

- **Collector / L1-L3**: discover leads, identify discovery surface, resolve article URL, acquire page/body, preserve raw evidence and replayable snapshots.
- **L4**: resolve canonical URL/source, publication date and provenance, source relationship, PageSurface, factual freshness.
- **L5**: editorial worth only.
- **L6**: policy, capacity, diversity and portfolio selection.

Non-negotiable separation:

> Collector outputs observations/evidence; L4 outputs resolved facts. Collector must not flatten uncertain date/source evidence into final canonical facts before L4.

Future primary Discovery authority is GitHub Collector. Scheduled ChatGPT/native discovery remains only a bounded transitional fallback and an independent audit/benchmark path. Do not build a second crawler inside the scheduled recommendation agent.

### 7.1 Two freshness clocks must remain separate

```text
A. workflow execution freshness
   scheduled_at -> actual Collector start

B. source revisit freshness
   source scan -> article publication -> next source scan -> report cutoff
```

Across 11 recent natural scheduled runs measured before the repair:

```text

workflow start delay p90    ~= 89m13s
workflow start delay max    =  93m30s
```

Workflow delay is material but was not the primary demonstrated benchmark cause.

### 7.2 Pre-repair selector contract

Active cap:

```text
native_source_scans_per_run = 8
```

Legacy source selection is:

```text
least-recently-scanned
+ priority-tier quota
+ same-day avoidance
```

Normal eight-slot split is approximately:

```text
rotate: 6
explore: 2
```

Enabled registry size at measurement time:

```text
English: 29
Chinese: 34
```

At two runs/language/day:

```text
English full-pass floor ~= 29 / 16 = 1.81 days
Chinese full-pass floor ~= 34 / 16 = 2.13 days
```

Therefore a universal sub-24-hour revisit SLA is mathematically impossible under the existing source-scan cap.

### 7.3 Anchor evidence

- **ProPublica**: scanned 2026-08-12 04:37; two benchmark pieces appeared later; neither later `intl_early` nor `pre_report` rescanned it before cutoff.
- **Atlantic AI panic**: published about 04:05 BJT; `pre_report` actually began around 04:28 but Atlantic was not selected because older sources were ahead in LRU rotation. This separates scheduler selection failure from GitHub start delay.
- **Jiemian**: scanned 2026-08-12 13:23, article published 15:09, same-day evening run did not rescan it, next confirmed scan 2026-08-13 18:50:41; publication-to-next-scan lag about 27h41m.
- **Yicai**: confirmed source revisit interval from 2026-08-11 18:42 to 2026-08-13 18:50:41 was about 48h08m. Exact target publication times are unavailable; do not invent them.
- **Quanta** remains ambiguous for precise historical lag.

Causal conclusion:

```text
coverage-oriented LRU
+ same-day avoidance
+ fixed 8-source cap
+ large source pools
      ↓
1-2+ day source revisit
      ↓
article published after prior scan
      ↓
no post-publication source scan before report cutoff
      ↓
URL never reaches Collector observable universe
```

Primary demonstrated issue = **source revisit policy/capacity**, not Acquisition, L4, frozen L5, or a missing generic crawler.
