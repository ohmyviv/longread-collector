## 2. Settled target architecture

```text
Source Registry
      ↓
GitHub Collector
  ├─ L1 Discovery
  ├─ L2 Acquisition Gate
  ├─ L3 Acquisition
  └─ raw observations / replayable snapshots
      ↓
L4 Canonical Article
      ↓
L5 Editorial Judge
      ↓
Candidate Universe
      ↓
L6 Policy / Portfolio Selection
      ↓
history / archive / delivery
```

Responsibilities remain strict:

- **Collector / L1-L3**: discover leads, identify discovery surface, resolve article URL, acquire page/body, preserve raw evidence and replayable run snapshots.
- **L4**: resolve canonical URL/source, publication date and provenance, source relationship, PageSurface, factual freshness.
- **L5**: editorial worth only.
- **L6**: policy, capacity, diversity and portfolio selection.

Non-negotiable separation:

> Collector outputs observations/evidence; L4 outputs resolved facts. Collector must not flatten uncertain date/source evidence into final `published_date` or `canonical_source` before L4.

Future primary Discovery authority is GitHub Collector. Scheduled ChatGPT/native discovery remains only a bounded transitional fallback and an independent audit/benchmark path. Do not build a second crawler inside the scheduled recommendation agent.

## 6. Phase 0A — durable Discovery snapshot invariant

### Trigger

The 48-hour benchmark window contained:

```text
run-reported discovery observations: 1300
persisted snapshot observations:     1114
coverage:                             85.7%
```

The entire 186-row block for:

```text
COL-20260812-042957-BJT-pre_report
```

was absent, while 32 `article_cache` rows from the same run survived.

Historical root cause is now reconciled: that exact run triggered PR #83 / PR-7.3.8 because a non-`metadata_json` snapshot cell exceeded Google Sheets' 50k single-cell ceiling. PR-7.3.8 already fixed the lossless all-cell overflow mechanism.

Phase 0A therefore did **not** redesign the writer. It closed the remaining fail-open observability gap.

### Merged implementation

PR #86 adds an opt-in post-persistence verifier for `v06_shadow` runs while preserving PR-7.3.8 writer identity.

After snapshot append it requires:

```text
expected_snapshot_rows
    ==
persisted rows whose collector_run_id == current run_id
```

On known write error or durable readback mismatch:

- snapshot audit fails closed;
- `collector_runs.final_status=failed`;
- error is exposed in run output;
- stable snapshot audit markers are written into existing `notes` without Sheet schema changes;
- GitHub Actions fails the explicit durable-snapshot assertion;
- evidence artifact still uploads via `if: always()`;
- `article_cache` is not rolled back.

No changes were made to source registry, source scheduling, Discovery ranking/caps, Acquisition routing/budgets, L4 semantics, frozen L5, L6, or promotion state.

### Phase 0A acceptance gate

**CI success is not Natural acceptance.** The first scheduled Collector run after merge commit `88dd31d...` must satisfy all of:


For each registered source/run, establish at least:

```text
source_id

query_group
route/discovery surface
last_attempt_at
last_success_at
articles/leads discovered
publication time of benchmark target where known
time from publication -> next source scan
time from last successful source scan -> report cutoff
```

The first questions are:

1. How long can a high-value registered source go without being selected again?
2. Which query groups are eligible to rescan it?
3. Did article publication happen shortly after the source's only scan for the day?
4. Did later scheduled runs skip the source because of rotation/cap logic?
5. Is the problem cadence/selection, or does the existing route itself fail to expose fresh URLs?

Only after this measurement should Phase 0B decide whether to modify:

- source rotation;
- minimum freshness/SLA logic;
- query-group eligibility;
- route-specific polling cadence.

Do not add another generic crawler as the first fix.

## 10. Collector -> L4 handoff principle

The handoff object should be an **Observation Bundle**, not a pre-resolved Canonical Article.

Conceptually:

```json
{
  "collector_run_id": "...",
  "source_id": "...",
  "discovery_surface": "homepage",
  "observed_title": "...",
  "observed_url": "...",
  "page_metadata": {},
  "publication_date_evidence": [],

  "page_surface_evidence": [],
  "body": {
    "status": "ok",
    "chars": 7200
  }
}
```

L4 then resolves canonical URL/source/date/source relationship/PageSurface using provenance-aware rules.

## 11. Promotion gates

Keep three independent gates.

### Transport Gate — current `READY`

Collector transport/acquisition mechanics are operational, but Phase 0A Natural acceptance still needs to prove the new durable snapshot invariant on a scheduled run.

### Editorial Gate — current `NOT_READY`

Requires repeated/multi-day ground-truth evidence that Collector supplies an editorial universe sufficiently close to the independent high-quality reference path. Selected/strong recall matters more than raw URL recall; Chinese recall must be reported separately.

### Promotion Gate — current `SHADOW`

Requires Editorial readiness plus:

- no material source blind spot;
- no systematic Chinese recall failure;
- no meaningful freshness regression;
- no L4 evidence-quality regression;
- stable multi-run operation;
- explicit cutover decision.

No automatic promotion.

## 13. Settled engineering invariants

- L5 remains frozen at `editorial-judge-v0.6-pr7.2` during this work.
- Facts, editorial assessment and policy state remain separate.
- Source chase is an action, not an editorial rejection.
- Capacity loss is not content rejection.
- Unknown/conflicting publication facts are not fabricated.
- URL date evidence remains contextual/weak unless independently supported.
- Evidence provenance must survive shared-acquisition/compatibility bridges.
- Same-day normalized date equality is not proof that two observations are the same evidence.
- Explicit source-relationship evidence outranks weak publisher-surface inference.
- Shadow paths must not silently duplicate paid/live acquisition requests.
- Network/acquisition budgets are not expanded inside L4 repair work.
- Snapshots/ground truth must be replayable.
- No synthetic historical observability rows are written merely to satisfy dashboards.
- Existing status/reason vocabulary should be preserved; derived cross-stage classification belongs in audit/metrics.
- Promotion decisions are explicit and data-driven.
