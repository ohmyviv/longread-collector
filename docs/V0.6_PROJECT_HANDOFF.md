## 2. Six-layer architecture contract

```text
L1 Discovery
  -> L2 Acquisition Gate
  -> L3 Acquisition
  -> L4 Canonical Article
  -> L5 Editorial Judge
  -> L6 Policy & Portfolio Selection
```

### L1 — Discovery

What URLs/evidence were found? Produces immutable discovery facts. It must not
make final editorial decisions.

### L2 — Acquisition Gate

Should acquisition budget be spent now? Hard reject is limited to deterministic,
low-regret cases. Unknown/conflicting dates are not silently fabricated.

### L3 — Acquisition

What body/metadata can be acquired, with what sufficiency/cost? Jina / Direct
HTML / Firecrawl remain explicit routes with unified budget accounting.

### L4 — Canonical Article

What content asset does this page represent? Resolves factual identity/evidence:

- title/author;
- publication/date evidence;
- hosting/canonical/original publisher;
- source relationship/action;
- canonical content identity;
- duplicate/freshness facts.

**Source chase is an action, not an editorial rejection.**

### L5 — Editorial Judge

How much editorial value/risk does the acquired content have? Technical failure
and source-chase need must not be rewritten as low editorial value.

### L6 — Policy & Portfolio Selection

Given freshness, capacity, diversity, redundancy and cost, what action should be
taken? Actions include select / source chase / defer / reject. Capacity loss is
not the same as content rejection.

Cross-layer principles:

- immutable stage outputs;
- facts, editorial assessment and policy state stay separate;
- explicit dependency injection;
- evidence-backed conclusions;
- one final compatibility projection rather than repeated terminal-state rewrites.

## 5. Settled publication/freshness boundaries

These rules are now part of the merged PR-7.1 + PR-7.3 L4 behavior and should not
be casually reopened:

1. Credible **article-local publication evidence outranks stale page/template
   timestamps**.
2. `updated`, `republished`, and `translated_published` are contextual date roles;
   they do not establish/refresh initial publication freshness by themselves.
3. Explicit `original_published` can establish initial publication while later
   republication remains contextual.
4. URL-path dates are weak/contextual-only and cannot establish publication by
   themselves.
5. A legacy aggregate whose own source says it is URL-derived must be demoted
   back to URL provenance.
6. URL-derived dates flattened by adapters into generic
   `published_at_hints` / `raw_dates` must not regain selectable provenance merely
   because they were copied through those channels.
7. No PR-7.1 fallback may resurrect a date after PR-7.3 has determined that only
   contextual/insufficient evidence exists.
8. Credible conflicts are explicit; same-semantic conflicts lower confidence.
9. `updated` vs `published`, or `issued` vs `published`, are not automatically
   conflicts because they are different semantic roles.
10. Timezone-bearing timestamps are normalized to Beijing (`UTC+8`) calendar
    date for the date-only canonical contract, with conversion basis retained in
    evidence.
11. Unknown/conflicting dates are not fabricated. `publication_date_unknown_defer`
    remains an acceptable safe outcome.

PR-7.1 downstream freshness policy remains in force, including standard
freshness boundaries and separate tracks for primary documents, academic papers,
and source chase.

### Final-review blocker fixed before merge

Final code review discovered a real full-parallel provenance bug:

- legacy/full-parallel adapters flatten publication facts into both
  `DiscoveryRecord.published_at_hints` and `AcquisitionBundle.raw_dates`;
- a URL-derived legacy aggregate could therefore be correctly demoted by
  PR-7.3 and then reappear as generic acquisition/discovery evidence;
- this could incorrectly re-establish `published_at`.

Fix merged in PR #73:

- retain the normalized value of the explicitly demoted URL-derived aggregate;
- strip only same-date adapter projections from generic hints/raw dates before
  publication resolution;
- preserve independent evidence with a different normalized date;
- keep the original URL date as contextual evidence.

A real adapter-shaped regression protects the blocker, plus a negative-control
test proves independent acquisition evidence is not removed.

## 8. Merged PR-7.3 — source relationship model

PR-7.3 continues the existing source contract. Relevant values include:

- `ORIGINAL`;
- `SECONDARY_REPUBLISH`;
- `WIRE_REPUBLISH`;
- `TRANSLATED_REPUBLISH`.

Evidence already present in acquired content may include:

- external `rel=canonical` targets;
- explicit original/source hyperlinks in Markdown;
- structured Reuters/AP author/dateline/byline/copyright/source evidence;
- explicit translation-source wording.

Existing actions remain:

- `REPLACE_WITH_ORIGINAL`;
- `FIND_ORIGINAL_ARTICLE`;
- retain/none where appropriate.

Same-host/direct parent-subdomain canonicalization is treated as the same hosting
site rather than automatic republish evidence.

If stronger evidence changes `canonical_content_url`, canonical `content_id` is
recomputed using the existing canonical identity invariant.

### People's Daily natural-replay case

A People.com.cn/CPC-hosted article contained both a local timestamp and a direct
People's Daily original link. PR-7.1 had labeled the host page `ORIGINAL`.
PR-7.3 correctly resolves this style of case as:

```text
source_relationship = SECONDARY_REPUBLISH
canonical/original publisher = 人民日报
source_action = REPLACE_WITH_ORIGINAL
canonical URL = already-acquired People's Daily original URL
```

No extra network request is made.

### Known non-blocking hardening risks

Final review did **not** find a merge blocker beyond the URL-provenance issue.
Two areas remain appropriate for natural-shadow observation rather than immediate
rule expansion:

- Reuters/AP attribution: `© Reuters`-style signals can theoretically be image
  credits rather than article authorship; watch for false-positive source chase.
- explicit source hyperlinks / sibling-domain canonical relationships: watch for
  links that are media home/section pages rather than original article targets.

Do not pre-emptively expand heuristics unless real scheduled-run evidence shows a
failure.
