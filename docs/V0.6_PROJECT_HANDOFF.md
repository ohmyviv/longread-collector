## 2. Architecture contract — settled target state

The long-term production chain is:

```text
Source Registry
      ↓
GitHub Collector
  ├─ Discovery
  ├─ Acquisition
  └─ raw observations / snapshots
      ↓
L4 Canonical Article
      ↓
L5 Editorial Judge
      ↓
Candidate Universe
      ↓
L6 / portfolio selection
      ↓
history / archive / delivery
```

The existing six-layer engineering model remains valid:

```text
L1 Discovery
  -> L2 Acquisition Gate
  -> L3 Acquisition
  -> L4 Canonical Article
  -> L5 Editorial Judge
  -> L6 Policy & Portfolio Selection
```

### Responsibility boundaries

**Collector / L1-L3** answers:

- what article leads exist;
- where they were discovered;
- whether an independent article URL can be resolved;
- whether the page/body can be acquired;
- what raw metadata/evidence was observed;
- what the exact per-run snapshot contained.

**L4** answers factual identity questions:

- canonical URL;
- canonical publisher/source;
- publication date and provenance;
- source relationship;
- PageSurface;
- factual freshness state.

**L5** answers editorial-value questions only.

**L6** applies freshness/capacity/diversity/redundancy policy and final portfolio selection.

### Critical rule: Collector outputs evidence, L4 outputs facts

Collector must not prematurely flatten raw observations into final `published_date`, `canonical_source`, or final source-relationship truth. It should hand L4 an observation/evidence bundle. This preserves the provenance guarantees built during PR-7.3.x.

### Critical rule: one long-term primary Discovery system

Future primary Discovery is the GitHub Collector. Scheduled ChatGPT/native search is transitional only:

1. a thin fail-safe while Collector is not promoted; and
2. an independent audit/benchmark path.

Do **not** evolve scheduled ChatGPT into a second full crawler. Avoid duplicating homepage, section, RSS, sitemap, search and acquisition logic in both systems.

## 9. Collector -> L4 handoff principle

The handoff object should be an **Observation Bundle**, not a pre-resolved Canonical Article.

Conceptually:

```json
{
  "collector_run_id": "...",
  "source_id": "...",
  "discovery_surface": "homepage",
  "observed_title": "...",
  "observed_url": "...",
  "page_metadata": {},
  "publication_date_evidence": [],
  "source_relationship_evidence": [],
  "page_surface_evidence": [],
  "body": {
    "status": "ok",
    "chars": 7200
  }
}
```

L4 then resolves canonical URL/source/date/source relationship/PageSurface using provenance-aware rules.

This separation is mandatory; it prevents the Collector from recreating the provenance-flattening failures PR-7.3.x has been fixing.

## 10. Promotion gates

Keep three independent gates.

### Transport Gate

READY means Collector runs reliably, snapshots persist, source surfaces and acquisition mechanics are operational, and infrastructure invariants hold.

Current status: `READY`.

### Editorial Gate

Requires multi-day ground-truth evidence showing that Collector supplies an editorial universe close enough to the independent manual/high-quality reference path. Selected/strong recall matters more than raw URL recall, and Chinese recall must be reported separately.

Current status: `NOT_READY`.

### Promotion Gate

Requires Editorial readiness plus:

- no material source blind spot;
- no systematic Chinese recall failure;
- no meaningful freshness regression;
- no L4 evidence-quality regression;
- stable multi-run operation;
- explicit cutover decision.

Current status: `SHADOW`.

No automatic promotion is permitted.

## 11. Transitional scheduled-agent fallback

Until Collector promotion, scheduled/native discovery may retain only a thin one-pass fallback when yield is obviously abnormal, for example very low verified-candidate yield or zero/near-zero Chinese verified candidates.

Constraints:

- one bounded fallback pass only;
- no recursive search/homepage/section/RSS/sitemap loops;
- no new crawler architecture inside the scheduled agent;
- fallback results remain useful as independent audit evidence;
- after Collector cutover, fallback should be limited to Collector-health failure or removed entirely.

This fallback is transitional and must not become the long-term Discovery authority.

## 13. Settled engineering invariants

These remain non-negotiable unless a dedicated reviewed PR changes them:

- production L5 is frozen at `editorial-judge-v0.6-pr7.2` during PR-7.3.x;
- facts, editorial assessment and policy state stay separate;
- source chase is an action, not an editorial rejection;
- capacity loss is not content rejection;
- unknown/conflicting publication facts are not fabricated;
- URL date evidence is contextual/weak unless independently supported;
- structured evidence provenance must survive compatibility/shared-acquisition bridges;
- same-day normalized date equality is not proof that two observations are the same evidence;
- explicit source-relationship evidence outranks weak publisher-surface inference;
- shadow paths must not silently duplicate paid/live acquisition requests;
- network/acquisition budgets are not expanded inside L4 repair PRs;
- snapshots/ground truth must be replayable;
- no synthetic historical observability rows are written merely to make dashboards look complete;
- promotion decisions are explicit and data-driven.
