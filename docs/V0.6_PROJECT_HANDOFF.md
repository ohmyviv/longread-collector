## 2. Settled target architecture

```text
Source Registry
      ↓
GitHub Collector
  ├─ L1 Discovery
  ├─ L2 Acquisition Gate
  ├─ L3 Acquisition
  └─ raw observations / replayable snapshots
      ↓
L4 Canonical Article
      ↓
L5 Editorial Judge
      ↓
Candidate Universe
      ↓
L6 Policy / Portfolio Selection
      ↓
history / archive / delivery
```

### Responsibility boundaries

**Collector / L1-L3** answers:

- what article leads exist;
- which first-party/search/feed surface produced them;
- whether an independent article URL can be resolved;
- whether the page/body can be acquired;
- what raw metadata/evidence was observed;
- what the exact per-run snapshot contained.

**L4** resolves deterministic article facts:

- canonical URL;
- canonical publisher/source;
- publication date and evidence provenance;
- source relationship;
- PageSurface;
- factual freshness state.

**L5** answers editorial worth only.

**L6** applies policy, capacity, diversity and portfolio selection.

### Non-negotiable separation

Collector outputs **observations/evidence**; L4 outputs **resolved facts**. Collector must not flatten uncertain date/source evidence into final `published_date` or `canonical_source` before L4.

### One long-term Discovery authority

Future primary Discovery is the GitHub Collector. Scheduled ChatGPT/native search is transitional only:

1. bounded fail-safe before Collector promotion; and
2. independent audit / benchmark path.

Do not build a second full crawler inside the scheduled recommendation agent.

## 9. Collector -> L4 handoff principle

The handoff object should be an **Observation Bundle**, not a pre-resolved Canonical Article.

Conceptually:

```json
{
  "collector_run_id": "...",
  "source_id": "...",
  "discovery_surface": "homepage",
  "observed_title": "...",
  "observed_url": "...",
  "page_metadata": {},
  "publication_date_evidence": [],
  "source_relationship_evidence": [],
  "page_surface_evidence": [],
  "body": {
    "status": "ok",
    "chars": 7200
  }
}
```

L4 then resolves canonical URL/source/date/source relationship/PageSurface using provenance-aware rules.

## 10. Promotion gates

Keep three independent gates.

### Transport Gate — current `READY`

Collector runs reliably, snapshots persist, acquisition mechanics operate, and infrastructure invariants hold.

### Editorial Gate — current `NOT_READY`

Requires repeated/multi-day ground-truth evidence showing that Collector supplies an editorial universe sufficiently close to the independent high-quality reference path. Selected/strong recall matters more than raw URL recall; Chinese recall is reported separately.

### Promotion Gate — current `SHADOW`

Requires Editorial readiness plus:

- no material source blind spot;
- no systematic Chinese recall failure;
- no meaningful freshness regression;
- no L4 evidence-quality regression;
- stable multi-run operation;
- explicit cutover decision.

No automatic promotion.

## 11. Transitional scheduled-agent fallback

Until Collector promotion, scheduled/native discovery may retain only a thin one-pass fallback when yield is obviously abnormal, e.g. very low verified yield or zero/near-zero Chinese verified candidates.

Constraints:

- one bounded fallback pass;
- no recursive search/homepage/section/RSS/sitemap loops;
- no second crawler architecture inside scheduled ChatGPT;
- fallback output remains useful as independent audit evidence;
- after Collector cutover, fallback is limited to Collector-health failure or removed.

## 13. Settled engineering invariants

- L5 remains frozen at `editorial-judge-v0.6-pr7.2` during PR-7.3.x.
- Facts, editorial assessment and policy state remain separate.
- Source chase is an action, not an editorial rejection.
- Capacity loss is not content rejection.
- Unknown/conflicting publication facts are not fabricated.
- URL date evidence remains contextual/weak unless independently supported.
- Evidence provenance must survive shared-acquisition/compatibility bridges.
- Same-day normalized date equality is not proof that two observations are the same evidence.
- Explicit source-relationship evidence outranks weak publisher-surface inference.
- Shadow paths must not silently duplicate paid/live acquisition requests.
- Network/acquisition budgets are not expanded inside L4 repair PRs.
- Snapshots/ground truth are replayable.
- No synthetic historical observability rows are written merely to satisfy dashboards.
- Promotion decisions are explicit and data-driven.
