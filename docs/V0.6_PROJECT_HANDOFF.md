## 2. Six-layer architecture contract

```text
L1 Discovery
  -> L2 Acquisition Gate
  -> L3 Acquisition
  -> L4 Canonical Article
  -> L5 Editorial Judge
  -> L6 Policy & Portfolio Selection
```

Key boundaries:

- L1 discovers URLs/evidence; it does not make final editorial decisions.
- L2 spends acquisition budget only under conservative gate rules.
- L3 acquires body/metadata with explicit route/cost accounting.
- L4 resolves factual identity, date/source provenance, canonical URL, source
  relationship/action and freshness facts.
- L5 assesses editorial value/risk; technical/source-chase states are not low
  editorial quality.
- L6 applies freshness/capacity/diversity/redundancy policy and produces select /
  source chase / defer / reject actions.

Cross-layer principles:

- immutable stage outputs;
- facts, editorial assessment and policy state stay separate;
- explicit dependency injection;
- evidence-backed decisions;
- one final compatibility projection;
- source chase is an action, not an editorial rejection;
- capacity loss is not content rejection.

## 5. Settled publication/freshness boundaries

These rules are settled across PR-7.1, PR-7.3, PR-7.3.1 and PR-7.3.2:

1. Credible article-local publication evidence outranks stale template/page
   timestamps.
2. `updated`, `republished`, and `translated_published` are contextual roles and
   do not establish/refresh initial publication freshness alone.
3. Explicit `original_published` may establish initial publication while later
   republication remains contextual.
4. URL-path dates are weak/contextual-only and cannot establish `published_at`
   alone.
5. A legacy aggregate explicitly marked URL-derived must be demoted back to URL
   provenance.
6. Adapter projections must not allow demoted URL evidence to regain selectable
   provenance.
7. Independent page metadata on the same calendar day as a URL hint must survive
   URL projection cleanup; equality of normalized date values is not proof that
   the evidence is the same observation.
8. Structured legacy publication evidence must cross the v0.5.6m -> v0.6 bridge
   with provenance intact.
9. Only `legacy_publication_date_candidate` evidence is carried across the
   zero-request shared-acquisition boundary for the provenance bridge; unrelated
   control evidence remains outside the shadow bundle.
10. Legacy `body_header_standalone_date` is article-local only when its raw date
    is actually present in a tight title-adjacent header window. A Related-card
    or distant occurrence is retained only as low-confidence acquisition
    evidence.
11. Generic flattened `raw_dates` duplicates are omitted when the same normalized
    value already exists as structured evidence, avoiding artificial conflicts.
12. URL evidence stays `contextual` in both selection semantics and the persisted
    evidence profile.
13. No PR-7.1 fallback may resurrect a date after the richer resolver determines
    that only contextual/insufficient evidence exists.
14. Credible same-semantic conflicts remain explicit and retain the PR-7.3
    confidence cap.
15. Timezone-bearing timestamps normalize to Beijing (`UTC+8`) calendar date for
    the date-only canonical contract, retaining conversion basis in evidence.
16. Unknown/conflicting publication dates are not fabricated;
    `publication_date_unknown_defer` remains a legitimate safety outcome.
17. PR-7.3.2 may recognize a standalone numeric absolute date/datetime only in a
    **tight title-local window**. This is a positive article-local cue, not a
    return to broad body-wide standalone-date scanning.
18. A distant Related/reference-card date must not become article-local merely
    because it appears in the acquired body.

PR-7.1 downstream freshness policy remains unchanged, including separate tracks
for primary documents, academic papers and source chase.

## 6. PR-7.3.1 natural-run blocker and fix

The first post-PR-7.3 natural `intl_early` run exposed one provenance-loss class
with two visible symptoms.

### C&EN false stale dates

Two C&EN pages had correct 2026 article dates but the frozen legacy standalone
body-date heuristic selected older Related-card dates (2025/2024). Correct
independent page metadata was still present in legacy freshness evidence, but the
v0.6 bridge had flattened away that provenance before L4 could use it.

### Same-day URL/page-metadata over-demotion

The New Humanitarian and similar pages could have both a weak URL-derived date
and an independent page-metadata timestamp on the same calendar date. PR-7.3's
value-based cleanup could remove both flattened projections, creating an
unnecessary `publication_date_unknown_defer`.

### PR-7.3.1 fix

Reference:

```text
docs/V0.6_PR7_3_1_DATE_PROVENANCE_HOTFIX.md
```

Implementation:

```text
src/longread_collector/v06/legacy/adapter_v0731.py
src/longread_collector/v06/canonical/publication_v0731.py
src/longread_collector/v06/canonical/service_v0731.py
src/longread_collector/v06/shadow/shared.py
```

The hotfix:

- preserves frozen legacy structured date candidates as immutable
  `legacy_publication_date_candidate` evidence;
- carries only those publication candidates through shared acquisition, keeping
  attempts/latency/cost zero and the StageEvent zero-request marker unchanged;
- maps page/discovery/body/URL sources back to explicit v0.6 provenance;
- preserves independent same-day page metadata when URL evidence is demoted;
- downgrades non-local `body_header_standalone_date` rather than allowing a
  Related-card date to outrank true page publication metadata;
- keeps URL-only evidence contextual and non-selectable;
- preserves genuine article-local conflict semantics.

The 2026-08-10 `zh_midday` natural run positively validated the same-day
page-metadata/provenance fix. PR-7.3.1 failed overall acceptance only because the
run exposed distinct new L4 gaps, not because the PR-7.3.1 provenance repair
regressed.

## 7. PR-7.3.2 natural-run blocker and L4 follow-up

Triggering run:

```text

runtime: collector-v0.6-pr7.3.1
GitHub workflow run: 31357779151

```

Engineering invariants passed, including full shared snapshot/body behavior with
zero shadow network requests, zero shadow Firecrawl requests, zero incremental
cost and zero body-fingerprint mismatch.

### Blocker A — explicit original-source links were missed

Natural examples included Huxiu pages explicitly stating:

- `本文来自微信公众号：[硅星人Pro](...)`
- `本文来自微信公众号：[宇众不同的露萱](...)`

and a ByDrug page with a title-adjacent `[查看原文](https://www.vbdata.cn/...)`.
PR-7.3 source resolution did not recognize those cues, so some republished pages
were incorrectly classified as `ORIGINAL`, including pages that reached the
selected set.

PR-7.3.2 adds only high-precision cues:

- named WeChat original attribution in the early article region;
- `[查看原文]`, `[原文链接]`, or `[原文]` only in a tight title-local window;
- target URL must be a credible external URL;
- ordinary external links and late references remain non-source evidence;
- existing wire and translated-republish relationships retain higher semantic
  precedence.

When triggered, the intended relationship is `SECONDARY_REPUBLISH` with
`REPLACE_WITH_ORIGINAL`, and the explicit original URL becomes the canonical
content URL.

### Blocker B — title-adjacent standalone datetime was underweighted

The ByDrug natural page displayed:

```text
2026-08-10 08:00 [查看原文](...)
```

immediately below the article title. It was a real article-local publication
fact, but it lacked a label such as `发布时间` / `Published`, so L4 left it too
weak and L6 correctly deferred under `publication_date_unknown_defer`.

PR-7.3.2 recognizes only a standalone numeric absolute date/datetime in a tight
title-local window as `body_header_standalone_datetime` article-local evidence.
It deliberately does not restore the legacy broad body scan.

Reference:

```text
docs/V0.6_PR7_3_2_L4_EVIDENCE_FOLLOWUP.md
```

Regression coverage includes the natural ByDrug/Huxiu shapes plus negative
controls for late reference links, while retaining the C&EN and The New
Humanitarian PR-7.3.1 regressions.

## 8. Source relationship model after PR-7.3.2

Supported relationships remain:

- `ORIGINAL`
- `SECONDARY_REPUBLISH`
- `WIRE_REPUBLISH`
- `TRANSLATED_REPUBLISH`

Relevant actions include `REPLACE_WITH_ORIGINAL` and `FIND_ORIGINAL_ARTICLE`.
Already-acquired original URLs may support replacement without new L4 network
requests. Hosting source and original publisher remain distinct concepts.

PR-7.3.2 adds evidence-backed original-source cues only where the page itself
explicitly exposes a credible external original. It does not treat arbitrary
external links as source evidence.

Known observation-only risks remain:

- `© Reuters`-style signals can theoretically be image credits rather than
  article wire attribution;
- explicit source links can theoretically target a publisher section/home page;
- sibling-subdomain source/canonical relationships may need later hardening;
- new title-local/original-link cues must be monitored for false-positive source
  replacement in scheduled natural runs.

Do not expand source heuristics further without concrete scheduled-run evidence.
