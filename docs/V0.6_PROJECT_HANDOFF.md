## 1. Project objective and migration posture

Repository: `ohmyviv/longread-collector`.

The active legacy control is:

```text

```

v0.6 is a six-layer replacement architecture developed and validated in shadow
before any production authority changes. The migration is deliberately
fail-closed.

Current production/migration principles:

- v0.5.6m remains the authoritative legacy control until an explicit canary
  decision;
- v0.6 may run in parallel shadow and consume shared discovery/body evidence;
- v0.6 shadow must not duplicate paid/live acquisition requests;
- the 32-body acquisition-attempt hard ceiling remains unchanged;
- Firecrawl budget/caps remain controlled by the existing run budget;

- there is no automatic promotion;

  acceptance days.

Legacy control should remain frozen except for exceptional defects such as
crashes, audit corruption, budget violations, or security issues.

## 2. Six-layer architecture contract

The target pipeline is:

```text
L1 Discovery
  -> L2 Acquisition Gate
  -> L3 Acquisition
  -> L4 Canonical Article
  -> L5 Editorial Judge
  -> L6 Policy & Portfolio Selection
```

### L1 — Discovery

Question: **what URLs and discovery evidence were found?**

Responsibilities include registered/native/open discovery, route/query/rank
metadata, URL hints, and immutable `DiscoveryRecord` output.

It must not decide final editorial candidacy.

### L2 — Acquisition Gate

Question: **should acquisition budget be spent on this URL now?**

Hard reject is limited to deterministic, low-regret cases. Unknown or
conflicting dates are not permanent rejections; they are acquired or deferred
according to the gate contract.

### L3 — Acquisition

Question: **what body and metadata can be acquired, with what cost and
sufficiency?**

Jina / Direct HTML / Firecrawl are explicit extractor routes. The output records
technical attempts and downstream sufficiency. Budget accounting is explicit.

### L4 — Canonical Article

Question: **what content asset does this page represent?**

L4 resolves factual identity and evidence, including:

- page surface;
- main content medium;
- editorial genre as a factual/structural descriptor;
- title and author evidence;
- publication/date evidence;
- hosting source, canonical source, original publisher;
- source relationship and source action;
- canonical content identity / duplicate facts;
- freshness facts.

**Source chase is an action, not an editorial rejection.**

### L5 — Editorial Judge

Question: **how much editorial value and risk does the acquired content have?**

It emits continuous value/risk dimensions and a structured verdict. Technical
failure and source-chase need must not be rewritten as low editorial value.

### L6 — Policy & Portfolio Selection

Question: **given daily policy, freshness, capacity, diversity, redundancy and
cost, what action should be taken?**

Actions include:

- `select_standard`;
- `select_special`;
- `source_chase`;
- `defer`;
- `reject`.

Capacity loss is not the same as editorial rejection.

### Cross-layer contract principles

- immutable stage outputs;
- facts, editorial assessment and policy state stay separate;
- explicit dependency injection rather than module-global replacement;
- evidence-backed conclusions;
- one final compatibility projection rather than repeated terminal-state
  rewrites.

## 4. Natural shadow and release-acceptance semantics

### Full-parallel engineering invariants

A scheduled full-parallel shadow run is not valid evidence unless the relevant
integrity conditions close, including:

- control run succeeds;
- shadow run succeeds/fails open without corrupting control;
- full control discovery snapshot is visible to shadow;
- shared acquired-body fingerprints match;
- shadow network request count = 0;
- shadow Firecrawl request count = 0;
- shadow incremental cost = 0;
- evidence artifact exists.

PR #66 was required because the first PR-7 scheduled runs had a snapshot capture
gap: legacy had the full discovery pool while shadow initially saw only the
acquired subset. Those early runs do **not** count as Natural Shadow Day 1.

### Release-acceptance counting rule

A semantic change that can affect downstream selection resets the natural
acceptance count. Specifically:

- merge/CI/replay/manual workflow dispatch do not count;
- scheduled natural shadow runs are the release-acceptance evidence;
- PR-7.1 reset the count;
- PR-7.2 reset the count;
- PR-7.3 will reset the count after merge because L4 canonical facts can change
  downstream freshness/source actions.

Do not silently carry an acceptance-day count across a semantic PR.

## 5. PR-7.1 — settled boundaries that PR-7.3 must preserve

PR-7.1 was triggered by the first usable natural shadow quality evidence.
Its relevant settled publication/freshness behavior is:

- credible **article-local publication evidence outranks stale page/template
  timestamps**;
- credible publication conflicts are explicit and lower confidence;
- resolved age is persisted as a canonical fact;
- standard longreads have a freshness safety boundary;
- ordinary content >14 days is rejected at policy/freshness level;
- 8–14 day high-quality deep-read exceptions are narrow and capacity-bounded;
- unknown or conflicting publication dates are **deferred**, not fabricated;
- primary documents, academic papers, and source-chase actions remain separate
  tracks.

In later quality review, `publication_date_unknown_defer` is a valid safe outcome
when no defensible publication date exists. Do not treat every defer as a false
negative.


PR-7.3 is intentionally **L4 Canonical Article only**. It has two factual
surfaces:

1. publication/date evidence;
2. source/original-publisher relationship evidence.

It performs no new network requests and does not source-chase inside L4.

### 7.1 Publication evidence model

The PR records date candidates with explicit structure rather than compressing
every date into one numeric priority.

Important fields/concepts:

- semantic role:
  - `published`;
  - `issued`;
  - `created`;
  - `original_published`;
  - `republished`;
  - `translated_published`;
  - `updated`;
  - `unknown`;
- provenance:
  - `article_header`;
  - `article_local_metadata`;
  - `page_metadata`;
  - `acquisition_metadata`;
  - `discovery_metadata`;
  - `url_path`;
- raw and normalized value;
- confidence;
- `timezone_basis`;
- relation to the selected fact:
  - `selected`;
  - `supports`;
  - `conflicts`;
  - `contextual`;
  - `alternative`.

The evidence profile is persisted in Canonical `freshness_facts` and field-level
`Evidence` rows.

### 7.2 Date-selection safety rules

The following are deliberate PR-7.3 rules:

1. **PR-7.1 provenance precedence is preserved.** Credible article-local evidence
   outranks weaker page/acquisition/discovery metadata.
2. Semantic specificity is applied after provenance; weak
   `originally published` metadata must not beat a strong article-header
   publication date merely because its semantic label sounds more specific.
3. `updated`, `republished`, and `translated_published` are contextual date roles
   and do not establish the initial publication date by themselves.
4. An explicit original-publication date may establish `published_at` while a
   later republication date remains contextual.
5. URL-path dates are contextual-only. They are not sufficient by themselves to
   establish `published_at`.
6. A legacy `published_at_resolved` aggregate is not trusted as stronger evidence
   when its own source label says it came from URL-path evidence; PR-7.3 demotes
   it back to its actual provenance.
7. No PR-7.1 fallback may revive a date after PR-7.3 has deliberately concluded
   that only contextual/insufficient evidence exists.
8. Conflicts are raised among credible candidates with the **same date semantic**
   rather than declaring `updated` vs `published` or `issued` vs `published` a
   false conflict.
9. Timezone-bearing timestamps are normalized to the Beijing (`UTC+8`) calendar
   date for the date-only Canonical contract, while the timezone conversion basis
   is retained in evidence.
10. Material publication conflicts retain the PR-7.1 low-confidence cap.
11. If no defensible initial publication fact exists, `published_at` stays
    unknown so downstream `publication_date_unknown_defer` remains available.

### 7.3 Article-header date recovery

PR-7.3 adds a narrow L4 preparation pass over body text already acquired by L3.
It can recover common Chinese media headers such as:

```text
**2026年08月08日08:12**来源：[原始媒体](https://original.example/article)
```

The timestamp is treated as article-local publication evidence when stronger
existing body evidence is absent. Markdown emphasis is tolerated.

Existing frozen `body_publication_evidence` must not be overwritten.

### 7.4 Source-relationship model

PR-7.3 continues the existing source contract; it does not invent a new policy
layer.

Relevant relationship values include:

- `ORIGINAL`;
- `SECONDARY_REPUBLISH`;
- `WIRE_REPUBLISH`;
- `TRANSLATED_REPUBLISH`.

Evidence consumed is already present in the acquisition bundle/body, including:

- external `rel=canonical` targets;
- explicit original/source hyperlinks in acquired Markdown;
- structured Reuters/AP author/dateline/byline/copyright/source evidence;
- explicit translation-source wording.

Actions continue to use existing source actions such as:

- `REPLACE_WITH_ORIGINAL`;
- `FIND_ORIGINAL_ARTICLE`;
- existing retain/none behavior where appropriate.

Same-host and direct parent/subdomain canonicalization are treated as one hosting
site rather than automatic republish evidence.

Reuters/AP negative controls are important: generic mentions, references, and
Thomson Reuters Foundation design/funding/partner credits are not sufficient to
classify a wire republish.

If stronger source evidence changes `canonical_content_url`, Canonical
`content_id` is recomputed to preserve the canonical identity invariant.

## 8. PR-7.3 natural-run replay findings

The main replay/design review used the most recent available scheduled
`pre_report` acquisition set at the time:

```text
COL-20260809-041344-BJT-pre_report
32 acquired/canonicalized items
old shadow runtime: PR-7.1
```

The review used the archived shadow result plus corresponding production
`article_cache` acquisition evidence. It was a regression/design replay, not a
release-acceptance day.

### Representation-only differences — no new rule

Sampled items from Knowable Magazine, Noema, The Atlantic, and The New Yorker
showed date differences that were largely timestamp/calendar representation or
evidence-source differences, not new semantic failures. PR-7.3 deliberately did
not add exceptions just because a diff existed.

### Correct unknown/defer behavior

A sampled PMC systematic review did not expose a reliable publication date in
the available evidence. Leaving it unknown/deferred is the safe result.

### Confirmed L4 source defect — People's Daily case

A China Communist Party News / People.com.cn-hosted item contained article-local
source evidence equivalent to:

```text
2026年08月08日08:12 来源：[人民网－人民日报](人民日报原文链接)
```

PR-7.1 Canonical had labeled the hosting page as `original`. This is a genuine L4
source-relation error because the acquired body itself identifies the People's
Daily original and supplies the original URL.

PR-7.3 now resolves this style of case as:

```text
source_relationship = SECONDARY_REPUBLISH
canonical/original publisher = 人民日报
source_action = REPLACE_WITH_ORIGINAL
canonical URL = already-acquired People's Daily original URL
```

No additional request is required.

A dedicated natural-replay-style regression protects this behavior.

### Weak URL/year heuristics — deliberately not expanded

Historical cache inspection shows that legacy `url_month_segment` evidence can
exist, e.g. turning a URL-level `2026-08` month into a synthetic
`2026-08-01`. Stronger post-acquisition evidence usually supersedes it.

The 2026-08-09 32-item replay set did not use `url_month_segment` as a final date
source. The inspected cache range had no `snippet_explicit_publication_year`
hits.

Therefore PR-7.3 does **not** expand into a broad rewrite of historical year/month
heuristics. The implemented rule is narrower: URL date evidence must not be
silently promoted into authoritative publication evidence.

## 9. PR-7.3 regression lessons already discovered

During hardening, new tests intentionally failed twice and exposed real
implementation defects.

### Defect 1 — inappropriate PR-7.1 fallback

An early PR-7.3 wrapper could decide that date evidence was insufficient and then
fall back to PR-7.1's aggregate `published_at`, silently reviving evidence which
PR-7.3 had demoted.

Resolution: the fallback was removed. PR-7.3 is evidence-authoritative for the
publication fact it resolves.

### Defect 2 — deep-frozen metadata mapping

`DiscoveryRecord.raw_metadata` is recursively frozen; nested metadata is a
`MappingProxyType`/mapping rather than a mutable `dict`. An early helper used
`isinstance(..., dict)`, which caused real freshness/body evidence to be missed.

Resolution: evidence preparation reads `collections.abc.Mapping` and preserves
existing frozen body-publication evidence.

These are useful reminders for future v0.6 work: immutable nested contracts are
intentional and must be read through mapping interfaces rather than mutable-dict
assumptions.

## 11. Frozen boundaries / do-not-regress list

Unless a new PR explicitly reopens one of these decisions, preserve the
following:

### Legacy and runtime safety

- legacy authoritative control = `collector-v0.5.6m`;
- no automatic v0.6 promotion;
- v0.6 primary remains disabled;
- 07:35 editor remains disconnected;
- no v0.6 primary cache authority;
- 32-body attempt ceiling unchanged;
- Firecrawl budget unchanged unless a dedicated budget PR says otherwise.

### Architecture

- facts / editorial assessment / policy remain separate layers;
- source chase is not an editorial rejection;
- technical acquisition failure is not low editorial value;
- capacity loss is not content rejection;
- immutable stage outputs stay immutable;
- no return to repeated module-global patch chains in v0.6.

### Date/freshness

- captured/first-seen time is not publication time;
- article-local credible publication evidence has priority over stale template
  timestamps;
- unknown/conflicting dates must not be fabricated into fresh dates;
- URL dates are weak/contextual unless stronger explicit evidence exists;
- update/republication/translation timestamps do not automatically refresh the
  original content's publication freshness;
- `publication_date_unknown_defer` is an acceptable safety outcome.

### Source relationships

- hosting source and original publisher are different concepts;
- source actions are independent of editorial quality;
- wire attribution requires strong evidence, not a generic Reuters/AP mention;
- an already-acquired explicit original URL can support
  `REPLACE_WITH_ORIGINAL` without an additional L4 network request.

### PR-7.3-specific

- do not change PR-7.2 L5 production implementation in PR-7.3;
- do not expand PR-7.3 into speculative fixes for every historical date
  heuristic;
- do not add network requests to L4;
- do not treat every legacy-vs-v0.6 difference as a bug; classify deltas as
  semantic fix / evidence enrichment / representation difference / regression.

## 12. Recommended review method for future semantic PRs

For a real-run replay/diff review, prefer a table with these concepts:

### Publication/date delta

- old selected value;
- old source/provenance;
- new selected value;
- new semantic role;
- new provenance;
- conflict/status;
- whether downstream freshness action changes.

### Source delta

- hosting source;
- old relationship/action/canonical source/URL;
- new relationship/action/canonical source/URL;
- evidence that caused the change.

### Classification of each delta

Use one of:

- **correct semantic fix**;
- **neutral evidence enrichment / representation difference**;
- **possible regression**;
- **insufficient evidence — keep defer/unknown**.

Do not optimize for reducing the number of diff rows. Optimize for factual
correctness and low-regret policy behavior.

- [ ] current authoritative legacy/shadow versions;
- [ ] PR ledger status;
- [ ] new settled decisions and frozen boundaries;
- [ ] relevant natural-run evidence and whether it counts for acceptance;
- [ ] current open PR / next action;

- [ ] latest meaningful validation state;

the authoritative artifact and record only the decision that future work must
