# Longread Collector v0.6 PR-3: Editorial Judge

Status: deterministic development implementation  
Baseline: `main@110d28e8` (`v0.6 PR-2`)  
Legacy control: `collector-v0.5.6m`  
Production integration: none

## 1. Purpose

PR-3 implements the L5 **Editorial Judge** from the v0.6 architecture.

The judge answers one question:

> Given a canonicalized content asset and the body evidence already acquired, how
> much editorial value does it have, and what editorial risks are present?

It does **not** decide the final daily policy action. In particular, it does not
write any of the legacy terminal states:

- `formal_candidate`;
- `special_candidate`;
- `reject`;
- `eligible_for_editor`.

Those compatibility fields remain outside the judge. Final actions such as
`select_standard`, `select_special`, `source_chase`, `defer` and `reject` belong
to PR-4 Policy & Portfolio Selection.

## 2. Inputs and output

Inputs:

- immutable `RunContext`;
- immutable `CanonicalArticle` from PR-2;
- immutable `AcquisitionBundle`.

Output:

- immutable `EditorialAssessment`.

The existing v0.6 contract exposes seven positive dimensions:

1. `substance_score`;
2. `original_reporting_score`;
3. `analysis_score`;
4. `argument_score`;
5. `evidence_density_score`;
6. `reader_value_score`;
7. `timeliness_relevance_score`.

Four risk dimensions remain independent:

1. `promotional_risk`;
2. `event_risk`;
3. `transcript_risk`;
4. `template_risk`.

All scores are normalized to `[0, 1]`.

## 3. Why risk is separate from substance

A recurring v0.5.6 failure was to treat a single page attribute as the final
content verdict.

PR-3 deliberately preserves competing facts. A long event preview may have high
substance but also high event/promotional risk. A television transcript may have
thousands of prose characters while remaining a television transcript.

Examples from the 2026-08-06 natural-run human audit:

| audited case | substance | dominant risk | PR-3 verdict |
|---|---:|---:|---|
| Reporter Ceuta longform | ~0.80 | low | `consider` |
| Turnintl policy analysis | ~0.89 | low | `consider` |
| Turnintl commander interview | ~0.81 | low | `consider` |
| CCTV `焦点访谈` transcript | ~0.75 | transcript ~0.98 | `reject` |
| Shanghai Book Fair preview | ~0.60 | event ~0.96 | `reject` |
| ideological/theory commentary | ~0.61 | low | `low_value` |

The last row is intentional: low editorial value is not the same thing as a
final policy rejection.

## 4. Evidence-based deterministic features

PR-3 does not use site or title whitelists. It derives observable features from
the acquired body and Canonical facts, including:

- prose length and document structure;
- interviews, reporting and field-reporting cues;
- attributed claims and quotations;
- numerical facts and outbound citations;
- analysis and argument transitions;
- event and promotion vocabulary;
- broadcast-program/transcript vocabulary;
- repetitive ideological rhetoric;
- market-data template vocabulary;
- template-to-prose ratio;
- factual publication age.

The `REPORTED_FEATURE` genre produced by PR-2 is deliberately broad. PR-3 does
not grant a high original-reporting score from that enum alone; it requires
observed reporting/attribution signals.

Embedded video count is not a transcript rule.

## 5. Timeliness is a score, not a freshness gate

`timeliness_relevance_score` is a continuous input to editorial utility.
PR-3 does not apply the production freshness policy.

This matters for special material. For example, the audited academic paper from
2026-07-10 is 27 days old relative to the 2026-08-06 run, so its timeliness
score is below 0.5, but PR-3 does not reject it merely for age. Whether it should
consume a daily selection slot belongs to PR-4.

Likewise, an old but intrinsically strong interview can retain high substance
and reporting scores while receiving low timeliness relevance.

## 6. Sufficiency and source chase

Acquisition failure is not editorial failure.

If `AcquisitionBundle.sufficient_for_editorial_judgment` is false, or the
Canonical page is an external-link shell/paywall/login/captcha/listing/homepage,
the judge emits:

`EditorialVerdict.INSUFFICIENT_EVIDENCE`

It does not emit `LOW_VALUE` or `REJECT`.

This preserves the architecture rule that a ThePaper→PeopleApp shell should
trigger source-chase work in another layer rather than be mistaken for a bad
article.

## 7. Verdict mapping

PR-3 computes a continuous utility from the seven positive scores and a
separate risk penalty. The initial deterministic calibration maps utility to:

- `recommend`: >= 0.68
- `consider`: >= 0.48
- `low_value`: >= 0.30
- `reject`: < 0.30

These are **EditorialVerdict** boundaries only. They are not production
selection thresholds.

A later model-assisted judge may implement the same `EditorialAssessment`
interface for ambiguous cases, but it still may not write final policy state.

## 8. Human-label development replay

The fixed development fixture is derived from the reviewed natural run:

- audit: `SHADOW-AUDIT-20260806-2018-BJT-V056M-ZHEVENING-FULL32`;
- run: `COL-20260806-195235-BJT-zh_evening`.

The fixture intentionally spans:

### Human high/medium, actionable

- Reporter Ceuta longform;
- Turnintl policy analysis;
- Turnintl field interview;
- sustained book review;
- legal commentary;
- PBOC primary document;
- academic paper.

### Human low

- ideological/theory commentary;
- CCTV program transcript;
- Shanghai Book Fair event preview;
- training-event recap;
- author/new-book promotion;
- short straight-news brief;
- market-data card.

### Insufficient body truth

- ThePaper external-link shell pointing to the original PeopleApp article.

Development replay result:

- actionable precision: `100%`;
- actionable recall: `100%`;
- serious false accepts: `0/3`;
- specialized tests: `25 passed`.

These figures are **not** a release claim. This is a golden/development replay
used for implementation calibration. Natural holdout data occurring after the
version is frozen remains separate and is required later.

## 9. Evidence and auditability

Every positive and risk dimension emits field-specific `Evidence` at
`StageName.EDITORIAL`, plus one verdict evidence record containing the
continuous utility and maximum risk.

The judge never mutates Canonical or Acquisition inputs.

## 10. Production safety boundary

PR-3 changes no active production behavior:

- no legacy `pipeline*` edits;
- no production classification edits;
- no runtime-config or Sheet writes;
- no selector changes;
- no new discovery or extraction requests;
- no Firecrawl changes;
- no change to the 32-attempt ceiling;
- no 07:35 editor connection;
- no automatic promotion.

`DEFAULT_V06_MANIFEST` advances only to:

- `architecture_version = collector-v0.6-pr3`;
- `migration_phase = pr3_editorial_judge`.

All production-safety booleans remain `False`.

## 11. Definition of done

PR-3 is complete when:

1. all 11 score/risk dimensions remain bounded and evidence-backed;
2. high/medium audited material stays actionable in the development replay;
3. all audited serious false accepts leave the actionable region;
4. low-value commentary is distinguishable from hard editorial rejection;
5. external-link shells return `INSUFFICIENT_EVIDENCE`;
6. embedded video count alone does not create transcript risk;
7. primary/academic material is not punished for lacking journalistic reporting;
8. existing repository tests pass;
9. no active legacy or production file changes.
