# Longread Collector v0.6 PR-6: Discovery + Acquisition Gate

Status: shadow architecture implementation  
Baseline: `collector-v0.6-pr5`  
Legacy control: `collector-v0.5.6m`  
Production integration: none

## 1. Purpose

PR-6 implements two architecture boundaries that were coupled in the legacy
prefilter:

```text
existing discovery outputs
  -> immutable DiscoveryRecord
  -> conservative Acquisition Gate
  -> ACQUIRE | DEFER | HARD_REJECT
```

PR-6 does not execute a new RSS, sitemap, section-scan, Firecrawl search or any
other discovery request. Existing discovery routes remain the data-producing
control. The new code only adapts their already-produced records into the v0.6
contract.

The main objective of the gate is deliberately asymmetric:

> hard reject only when the evidence is strong enough that acquiring the page is
> very unlikely to change the decision.

Missing evidence is not negative evidence.

## 2. Why the legacy boundary changes

The v0.5.6m prefilter currently combines three different questions:

1. what kind of URL/page was discovered;
2. whether its publication date satisfies the daily freshness policy;
3. whether it deserves one of the limited acquisition slots.

That coupling caused repeated guard patches. A title containing a podcast,
program, conference or institution term could look like a non-article page even
when it was a reported article about that subject. Unknown publication dates
could be rejected before the body had a chance to provide a date. A 4–14 day
article could be killed merely because the discovery title lacked an explicit
"depth" keyword.

PR-6 makes the pre-acquisition gate narrower.

## 3. Discovery adapter

`DiscoveryAdapter` accepts the current discovery object shape by structural
fields; it does not import or mutate the legacy `DiscoveredURL` model.

It preserves:

- original URL;
- canonical URL hint;
- title and description hints;
- all publication hints it can observe;
- source id/name;
- discovery method and endpoint/query;
- rank;
- external/original-link hints;
- raw route metadata;
- field-level evidence.

Native discovery metadata such as `source_id`, `source_name`, `native_method`,
`native_endpoint` and `priority_tier` therefore survives intact.

Publication-hint confidence is route-aware. RSS/Atom and news-sitemap dates are
strong discovery evidence. Generic sitemap/search/section hints remain lower
confidence. The adapter never converts a low-confidence hint into a hard
freshness conclusion.

Every adaptation can also emit a `DISCOVERY_RESULT` StageEvent, allowing PR-7 to
join the existing StageEvent chain without changing PR-6 behavior.

## 4. Acquisition Gate contract

The gate consumes only:

- immutable `DiscoveryRecord` facts;
- immutable `GateContext` supplied by the caller.

`GateContext` carries the evaluation clock, the ordinary-media age ceiling and
an optional set of exact already-known canonical URLs. It performs no Sheet or
network read.

The gate returns one immutable `GateDecision` plus a `GATE_RESULT` StageEvent.

## 5. Hard-reject allowlist

PR-6 uses an allowlist, not a growing blacklist. Hard reject is limited to
high-confidence cases:

### 5.1 Invalid URL

Non-HTTP(S), missing-host and otherwise unusable URLs cannot be acquired as web
articles.

### 5.2 Root homepage

A bare host root is a source surface, not a content asset.

### 5.3 Explicit authentication/captcha route

Examples include `/login`, `/signin`, `/auth` and `/captcha`.

### 5.4 Explicit search/category/tag/topic index

The path must itself identify an index route. A title merely mentioning a topic
is not sufficient.

### 5.5 Job/career route

Explicit `/jobs`, `/careers` and `/vacancies` paths are rejected.

### 5.6 Exact known duplicate URL

Only a canonical URL supplied through `GateContext.known_duplicate_urls` is a
pre-acquisition duplicate hard reject. Fuzzy title similarity is not.

### 5.7 Magazine issue landing

The validated v0.5.6m rule remains narrow: both a `/magazine/<id>.html`-style
path and a `20xx年第N期`-style issue title are required. A real article under the
same path family is not rejected.

### 5.8 Authoritative stale ordinary article

An ordinary media item may be hard rejected as stale only when:

- a publication hint has high confidence;
- high-confidence hints do not conflict materially;
- the resolved date is older than the ordinary policy ceiling (currently 14
  days);
- the item does not strongly resemble a primary/special/academic document.

PDFs, academic domains, clear policy/guidance documents and government primary
materials do not inherit the ordinary 14-day hard gate.

## 6. What is intentionally not a hard reject

The following discovery-only signals are **not** sufficient for permanent
rejection in PR-6:

- unknown publication date;
- conflicting publication dates;
- a reported article discussing a podcast;
- a reported article discussing a degree/program;
- a reported article about a conference/event;
- a training/opening headline;
- an event preview headline;
- a television-program headline;
- a press-release marker;
- a newsletter/roundup marker;
- a correction marker;
- a market-report phrase;
- institution/profile words in an otherwise plausible article route;
- being 4–14 days old without a discovery-title "depth" keyword.

Those cases either proceed to acquisition or, when evidence itself is
internally inconsistent, are deferred rather than destroyed.

PR-3 Editorial Judge and PR-4 Policy remain responsible for deciding whether a
fully understood content asset is worth selecting.

## 7. Date semantics

The gate distinguishes four states:

### Unknown

No authoritative date exists. Result: `ACQUIRE` unless another deterministic
hard gate applies.

### Low-confidence date

Useful as a priority feature but never sufficient for a hard freshness reject.

### Conflicting high-confidence dates

Result: `DEFER` with `publication_date_conflict`. The conflict must be resolved
from acquisition/canonical evidence.

### High-confidence future date

Result: `DEFER`, not hard reject. Time-zone or metadata mistakes can produce
future hints and acquisition may resolve them.

### High-confidence stale ordinary-media date

Result: `HARD_REJECT` only under the allowlist conditions above.

## 8. Priority features

For items that survive the deterministic gate, the decision records numeric
features for later planning rather than trying to make a portfolio decision:

- registered-source indicator;
- article-path signal;
- special-document hint;
- best publication confidence;
- discovery rank signal;
- semantic-ambiguity indicator.

PR-6 does not choose the 24+4+4 acquisition plan. PR-4 owns the planner.

## 9. Gate evaluation metrics

`evaluate_gate_replay` reports the metrics appropriate to a destructive early
gate:

- hard-reject count;
- hard-reject precision;
- false hard rejects;
- high-value false hard rejects.

The fixed regression suite requires zero hard rejects of known high-value
examples. The architecture release target remains hard-reject precision >=98%.
A fixed development replay is not a natural holdout result.

## 10. StageEvent behavior

Discovery adaptation emits `DISCOVERY_RESULT`.

Gate evaluation emits `GATE_RESULT` with:

- gate action;
- confidence;
- reason code;
- estimated acquisition cost;
- priority features.

Flow status maps as:

```text
ACQUIRE     -> PASS
DEFER       -> DEFER
HARD_REJECT -> REJECT
```

No compatibility candidate disposition is written at this stage.

## 11. Production safety boundary

PR-6 does **not**:

- edit or call a new legacy `pipeline*` entrypoint;
- replace the active v0.5.6m prefilter;
- execute discovery network requests;
- add Firecrawl requests;
- write Sheet/runtime configuration;
- change the 32-item acquisition ceiling;
- change Firecrawl daily/group budgets;
- connect the 07:35 editor;
- enable primary cache writes;
- enable automatic promotion.

The manifest advances only to:

```text
architecture_version = collector-v0.6-pr6
migration_phase = pr6_discovery_acquisition_gate
```

All production-safety booleans remain false.

## 12. Definition of done

PR-6 is complete when:

1. current discovery objects can be adapted without mutation;
2. source/route/date/external-link evidence is preserved in DiscoveryRecord;
3. importing the new discovery/gate packages does not activate legacy pipeline
   modules;
4. unknown dates are never hard rejected solely because they are unknown;
5. conflicting/future dates defer instead of permanent rejection;
6. semantic title classes such as podcast/event/program/training do not become
   pre-body hard rejects;
7. exact known duplicates and deterministic index/auth/job/homepage routes are
   hard rejected;
8. authoritative stale ordinary-media dates are hard rejected while special
   documents remain exempt from the ordinary age gate;
9. fixed high-value replay has zero false hard rejects;
10. all existing and new tests pass;
11. active production behavior remains unchanged.
