# Longread Collector v0.6 PR-1: Legacy Adapter and StageEvent

Status: implementation contract  
Baseline: `collector-v0.5.6m`  
Mode: offline compatibility projection  
Production behavior: unchanged

## Scope

PR-1 adds a read-only bridge from completed v0.5.6m objects to the immutable
v0.6 contracts introduced in PR-0.

It provides:

- `LegacyV056mAdapter`;
- deterministic and immutable `StageEvent` records;
- event-derived run metrics;
- comparison with compatible legacy run-summary counters;
- lifecycle-closure diagnostics.

It does not connect to the active pipeline, write Google Sheets, make network
requests, change legacy decisions, assign new editorial scores, or alter feature
flags and editor routing.

## Import boundary

The adapter is available only through an explicit import:

```python
from longread_collector.v06.legacy import LegacyV056mAdapter
```

Importing `longread_collector.v06` must not load legacy models, pipeline modules,
classification modules, or the adapter. This preserves the PR-0 guarantee that
v0.6 cannot change production through import side effects.

## Input and output

Input:

```text
RunContext
Iterable[(DiscoveredURL, ExtractedArticle)]
Optional legacy run summary
```

Each item becomes a frozen `LegacyAdaptedItem` containing:

```text
DiscoveryRecord
GateDecision
AcquisitionBundle
CanonicalArticle
EditorialAssessment
SelectionDecision
FinalProjection
StageEvent[]
```

A run becomes a frozen `LegacyAdaptedRun` containing all adapted items, the
flattened event stream, `StageEventMetrics`, and an optional
`LegacySummaryComparison`.

## Conservative mapping rules

The adapter is a compatibility projection, not the new canonical or editorial
engine.

- Legacy objects are never mutated.
- `FinalProjection` copies `candidate_disposition`, `eligible_for_editor`,
  `reject_reason`, `canonical_source`, and `source_action` exactly.
- All continuous editorial scores remain `0.0` and
  `editorial_value=legacy_unscored`.
- `original_source_required` maps to the explicit `source_chase` action rather
  than a new rejection.
- Page, content, and source enums are mapped shallowly; raw legacy values remain
  attached as evidence. PR-2 owns new canonical interpretation.

Compatibility verdicts are:

| Legacy disposition | v0.6 compatibility verdict |
|---|---|
| `formal_candidate` | `recommend` |
| `special_candidate` | `consider` |
| `original_source_required` | `insufficient_evidence` |
| `reject` | `reject` |

## StageEvent contract

PR-1 extends `StageEvent` with:

```text
event_type
attributes
```

Attributes are recursively frozen. Event IDs are deterministic from:

```text
run_id + item_id + event_type + ordinal
```

Every adapted item must contain exactly one of each result event:

```text
discovery_result
gate_result
acquisition_result
canonical_result
editorial_result
selection_result
projection_result
```

Zero or more `extractor_attempt` events may occur between gate and acquisition
result. Events form one parent chain, so missing and duplicate stages are
mechanically detectable.

## Extraction attempt semantics

Each legacy extraction attempt records:

```text
extractor
request_sent
request_outcome
body_chars
prose_chars
credits_used
latency_ms
error_type
```

For Firecrawl, the existing v0.5.6 operational classifier remains authoritative:

```text
request_succeeded
request_failed
skipped_group_cap
skipped_daily_cap
```

Budget-skipped attempts do not count as requests sent.

## Event-derived metrics

`StageEventMetrics` is calculated only from the event stream. It includes:

- event, item, stage, event-type, technical-status, and flow-status counts;
- disposition and selection-track counts;
- extractor attempt, request, success, failure, and skip counts;
- successful final extractor counts;
- acquisition success and failure counts;
- eligible-for-editor count;
- Firecrawl sent, succeeded, failed, and budget-skip counters;
- recorded cost;
- lifecycle closure errors.

No metric reads mutable legacy objects after events are produced.

## Legacy summary comparison

When a legacy summary is supplied, PR-1 compares only fields with compatible
semantics:

```text
jina_success
firecrawl_success
failed
requests_sent
requests_succeeded
requests_failed
requests_skipped_group_cap
requests_skipped_daily_cap
```

Missing fields are ignored. Differences remain diagnostic and never modify or
fail the legacy run.

## Definition of done

PR-1 is complete when:

1. legacy objects map without mutation;
2. terminal projection is exact;
3. editorial fields remain explicitly unscored;
4. source chase remains an action;
5. Firecrawl budget skips are not counted as sent requests;
6. event IDs and parent order are deterministic;
7. complete adapted items have 100% lifecycle closure;
8. missing terminal events produce closure errors;
9. compatible legacy summary counters can close against event-derived metrics;
10. root v0.6 import isolation remains intact;
11. full repository tests pass;
12. no active production file or configuration changes.

PR-2 will implement Canonical Article semantics against immutable cache replays,
using this compatibility projection as the control.
