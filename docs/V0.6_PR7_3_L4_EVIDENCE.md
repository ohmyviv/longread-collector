# v0.6 PR-7.3 — L4 Date Evidence & Source Relationships

## Scope

PR-7.3 is intentionally limited to **L4 Canonical Article**.

It improves two factual resolution surfaces:

1. publication-date evidence; and
2. hosting/original-publisher source relationships.

PR-7.2's L5 Editorial Judge is frozen. No PR-7.3 production code changes are
made under `v06/editorial/`.

## Why this PR exists

PR-7.1 fixed the most important freshness failure by preferring article-local
publication evidence over stale page/template timestamps and by surfacing
material conflicts. That safety boundary remains the compatibility baseline.

The remaining L4 weakness is evidence structure. PR-7.1 still compresses a date
candidate into a source label, numeric priority, and `article_local` boolean.
That loses distinctions which matter for audit and source chasing:

- published vs updated vs originally published vs translation/republication date;
- article header vs page metadata vs acquisition/discovery hints;
- date-only values vs timezone-bearing timestamps;
- supporting vs conflicting vs contextual evidence;
- hosting page vs canonical/original publisher;
- ordinary republish vs wire-service or translated republish.

PR-7.3 makes those relationships explicit without adding network requests.

## Publication evidence model

`publication_v073.py` records each observed candidate with:

- `source` — extractor/metadata origin;
- `semantic` — `published`, `issued`, `created`, `original_published`,
  `republished`, `translated_published`, `updated`, or `unknown`;
- `provenance` — article header/local metadata/page metadata/acquisition metadata/
  discovery metadata/URL path;
- `article_local`;
- raw and normalized values;
- confidence;
- `timezone_basis`;
- relation to the resolved fact: `selected`, `supports`, `conflicts`,
  `contextual`, or `alternative`.

The complete profile is persisted in
`CanonicalArticle.freshness_facts["publication_evidence_profile"]` and the
summary state in `publication_evidence_status`.

The model deliberately preserves multiple date roles instead of treating every
observed date as one interchangeable `published_at` candidate.

### Date-selection safety rules

- **PR-7.1 provenance priority is preserved.** Credible article-local header/body
  evidence outranks weaker page, acquisition, or discovery metadata. Semantic
  specificity is used only after provenance, so weak `originally published`
  metadata cannot override a strong article-header publication date.
- `updated`, `republished`, and `translated_published` are contextual evidence.
  None can establish the initial `published_at` by itself. This prevents a new
  update, translation, reprint, or republication timestamp from silently
  refreshing old/unknown content for downstream freshness policy.
- If an explicit `original_published` date coexists with a later republication
  date at the same article-local evidence level, the original date can establish
  `published_at` while the republication date remains visible as contextual
  evidence.
- URL-path dates, including URL-embedded Unix timestamps, are retained as weak
  context but are not promoted by themselves.
- Conflicts are raised only among credible candidates with the **same date
  semantic**. An `updated` or `republished` date therefore does not conflict with
  a `published` date; an official document's `issued` and `published` dates can
  coexist.
- Timezone-bearing timestamps are converted to the Beijing (`UTC+8`) calendar
  date before the date-only Canonical contract is populated. The conversion
  basis remains in the evidence profile.
- PR-7.1 conflict confidence capping remains: a material conflict caps resolved
  publication confidence at 0.45.
- If only contextual date roles are available, Canonical `published_at` remains
  unknown. Downstream PR-7.1 freshness policy can therefore keep the existing
  `publication_date_unknown_defer` behavior rather than inventing freshness.

## Source relationship model

`source_resolution_v073.py` runs over the PR-2 source resolver and only overrides
it when stronger acquired evidence exists.

This is a continuation of the existing source contract, not a new editorial
policy. The project already distinguishes original, translated, wire-service,
and secondary republication relationships and separately tracks hosting,
canonical, and original publishers.

New L4 evidence consumed by PR-7.3 includes:

- external `rel=canonical` targets already present in
  `AcquisitionBundle.raw_canonical_links`;
- Reuters/AP structured author, dateline, byline, copyright, source-label, and
  explicit-original signals;
- explicit translation-source wording.

The resolver maps those facts into the existing immutable contract:

- `ORIGINAL`;
- `WIRE_REPUBLISH`;
- `TRANSLATED_REPUBLISH`;
- `SECONDARY_REPUBLISH`;
- existing source actions such as `FIND_ORIGINAL_ARTICLE` and
  `REPLACE_WITH_ORIGINAL`.

Same-host and direct parent/subdomain canonicalization is treated as the same
hosting site rather than a republish. A plain mention of Reuters,
bibliography/reference text, or Thomson Reuters Foundation design credit is not
sufficient wire attribution.

## Persistence and audit

PR-7.3 does not add a new cross-layer mutable contract.

- Resolved source fields continue to use the existing `CanonicalArticle` fields.
- Source reasoning is persisted as field-specific `Evidence` rows.
- Publication candidates and date roles are persisted in immutable
  `freshness_facts` plus field-specific evidence rows.
- `content_id` is recalculated if stronger source evidence changes the canonical
  content URL, preserving the existing Canonical identity invariant.

## Deliberate non-goals

PR-7.3 does **not** change:

- L1 Discovery;
- L2 Acquisition Gate;
- L3 acquisition clients, request order, or request counts;
- the 32-body attempt ceiling or Firecrawl cap;
- L5 Editorial Judge scoring, thresholds, template recovery, newsletter guard,
  or short-news guard from PR-7.2;
- L6 freshness windows, portfolio ranking, diversity, capacity, or source caps;
- legacy `collector-v0.5.6m` production authority;
- primary cache writes;
- the 07:35 editor connection;
- automatic promotion.

No source chase performs network I/O inside L4. PR-7.3 only interprets evidence
which has already been acquired.

## Regression requirements

PR-7.3 must preserve the PR-7.1 and PR-7.2 tests and add coverage for:

1. UTC timestamps crossing the Beijing calendar boundary;
2. published + updated dates without a false conflict;
3. republication-only dates remaining contextual and not resetting freshness;
4. original-publication + republication dates remaining distinct;
5. translation publication dates remaining contextual;
6. article-header publication evidence beating weaker page metadata;
7. same-semantic article-local conflicts;
8. URL dates retained as context only;
9. external canonical links resolving a secondary republish;
10. same-host and parent/subdomain canonical links remaining original;
11. Reuters/AP wire republish evidence;
12. Thomson Reuters Foundation / mention-only false-positive controls;
13. explicit translated-republish evidence;
14. an explicit assertion that the active L5 judge version remains
    `editorial-judge-v0.6-pr7.2`.

## Release semantics

The shadow semantic version advances to `collector-v0.6-pr7.3`; legacy control
remains `collector-v0.5.6m`.

Because L4 canonical facts can change downstream freshness/source actions,
release-acceptance counting restarts from zero for PR-7.3 after merge. CI and
manual replay are regression evidence; scheduled natural shadow days remain the
release-acceptance evidence.
