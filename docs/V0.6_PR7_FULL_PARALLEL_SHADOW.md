# Longread Collector v0.6 PR-7: Full Parallel Shadow

Status: runtime shadow integration  
Legacy control: `collector-v0.5.6m`  
Shadow: `collector-v0.6-pr7`  
Primary output authority: legacy only

## 1. Purpose

PR-7 is the first runtime integration of the complete v0.6 decision stack.
It is deliberately a **sidecar**, not a second collector.

A natural control run performs discovery and acquisition exactly once. PR-7
then reuses:

- the same complete discovery snapshot already observed by the legacy filter;
- the same bodies and metadata already acquired by legacy;
- the same run id and scheduling context.

The v0.6 side evaluates those facts independently through:

```text
Discovery
  -> Acquisition Gate
  -> shared control acquisition evidence
  -> Canonical Article
  -> Editorial Judge
  -> Policy & Portfolio
```

No v0.6 discovery client or extractor is called by the shadow runner.

## 2. Control remains authoritative

`pipeline_v056f.NativeCollectorPipeline` remains the only control that decides
and writes:

- article cache contents;
- extraction logs;
- collector run rows;
- legacy candidate dispositions;
- source-chase behavior;
- Firecrawl budget consumption.

PR-7 does not edit the frozen v0.5.6m pipeline modules. Instead,
`ParallelShadowCollectorPipeline` subclasses the final control and calls
`super()` first.

The only active routing change is in the CLI: an explicit, validated runtime
flag can select the sidecar wrapper. If the flags are absent, the CLI still
selects legacy-only execution.

## 3. Explicit runtime activation

The scheduled GitHub workflow sets:

```text
PIPELINE_ENGINE=v06_shadow
V06_SHADOW_ENABLED=true
V06_WRITE_MODE=events_only
V06_PRIMARY_ENABLED=false
AUTO_PROMOTE_WHEN_READY=false
EDITOR_0735_CONNECTED=false
```

`v06_primary` remains forbidden by the PR-7 CLI router even if someone supplies
otherwise-valid primary flags. Primary authority is reserved for PR-8.

The Python feature-flag defaults themselves remain fail-closed and legacy-only.

## 4. Complete discovery snapshot without a second scan

The legacy v0.5.6 selection layer already exposes a ContextVar-based recall
capture. PR-7 opens that capture around the control run.

The existing legacy filter therefore records, in memory:

- every URL in the discovery pool presented to the filter;
- accepted-for-extraction items;
- deterministic prefilter rejects;
- reserve/capacity items not acquired;
- source-chase discovery rows processed later in the same run.

PR-7 does not run RSS, Atom, sitemap, section scan or Firecrawl Search again.
The snapshot is observed as a by-product of the control's existing work.

## 5. Shared acquisition evidence

For every body already acquired by control, the legacy compatibility adapter
first projects the frozen control item into the v0.6 acquisition contract.

`share_control_acquisition()` then creates a new immutable shadow bundle with:

- identical body markdown/text;
- identical title/author/date/link facts;
- identical sufficiency facts;
- **no shadow extractor attempts**;
- `total_cost = 0`;
- `total_latency_ms = 0`.

The shadow bundle records control attempt counts as provenance only.

This prevents the v0.6 StageEvent stream from double-counting Jina, Direct HTML
or Firecrawl work performed by the control.

Hard invariants:

```text
shadow_request_count = 0
shadow_firecrawl_request_count = 0
shadow_incremental_cost = 0
body_fingerprint_mismatches = 0
```

A shared acquisition event includes the SHA-256 body fingerprint and the
control request counts used to prove provenance.

## 6. Gate truth versus diagnostic truth

PR-7 deliberately distinguishes **effective flow** from **diagnostic flow**.

If v0.6 Gate says `ACQUIRE` and control already has a body, the item proceeds
normally through Canonical, Editorial and Policy/Portfolio.

If Gate says `HARD_REJECT` or `DEFER` but control happened to acquire the body,
PR-7 still computes Canonical and Editorial facts *diagnostically*. This is
important because the already-paid body can reveal a false hard reject.

However, such an item cannot enter the effective v0.6 portfolio. Its comparison
record is marked `diagnostic_only=true`.

This prevents the audit implementation from hiding Gate mistakes while still
preserving the real counterfactual policy path.

## 7. Unacquired discovery items

A URL that appears in the shared discovery snapshot but was not acquired by
legacy has no body truth in PR-7.

PR-7 therefore runs only:

```text
Discovery -> Acquisition Gate
```

for that item.

If Gate passes, the effective action is recorded as:

```text
defer / body_not_observed_in_control
```

The system does **not** fabricate Canonical or Editorial truth and does not
claim that the observed-body portfolio measures full-discovery recall.

This limitation is explicit in every run payload:

```text
unacquired_items_have_gate_only_truth = true
portfolio_is_observed_body_subset_only = true
```

## 8. Observed-body portfolio

Policy & Portfolio receives only items satisfying both:

1. v0.6 Gate action is `ACQUIRE`;
2. the control already obtained the body.

This produces an **observed-body v0.6 portfolio**, not a claim about the ideal
counterfactual portfolio over every discovered URL.

The default bounded portfolio remains 10 selections. Source chase remains a
separate action.

PR-7 reports legacy actionable items and v0.6 observed actionable items with an
explicitly named overlap/Jaccard metric. This is descriptive disagreement, not
a quality metric.

Quality improvement still requires human labels.

## 9. Per-item comparison

Each discovery row receives a compact comparison record containing:

- prefilter status/reason;
- whether control acquired it;
- v0.6 Gate action/reason;
- legacy candidate disposition;
- legacy projected policy action;
- v0.6 Editorial verdict when body truth exists;
- effective v0.6 policy action;
- selection status/rank;
- diagnostic-only flag;
- body fingerprint;
- difference tags.

Difference tags include:

- `gate_rejects_legacy_actionable`;
- `policy_action_disagreement`;
- publication disagreement;
- page-surface disagreement;
- medium disagreement;
- genre disagreement;
- source-relationship disagreement;
- source-action disagreement;
- editorial-verdict disagreement;
- `control_did_not_acquire_gate_pass`.

These tags localize disagreements by architecture layer before any human
quality judgment is applied.

## 10. StageEvent chain

The shared shadow emits one auditable event chain per observed item:

```text
DISCOVERY_RESULT
  -> GATE_RESULT
  -> ACQUISITION_RESULT (shared_from_control; zero request)
  -> CANONICAL_RESULT
  -> EDITORIAL_RESULT
  -> SELECTION_RESULT
```

Unacquired items emit Discovery, Gate and a terminal Selection/Defer event only.

The artifact contains compact event metadata and attributes rather than full
body/evidence excerpts. A deterministic SHA-256 digest covers the compact event
stream.

## 11. Failure semantics

The runtime sidecar is strictly fail-open.

If the control fails, the collector run still fails normally.

If the control succeeds but the v0.6 shadow throws any exception:

- the exception is caught after control completion;
- the legacy result remains successful and unchanged in authority;
- `v06_shadow.status = failed_open`;
- zero-request counters remain explicit;
- no primary state is written.

A shadow bug must never convert a successful v0.5.6m run into a failed
production collection run.

## 12. Persistence without Sheet schema changes

PR-7 intentionally does not add or modify Google Sheet tabs.

The scheduled workflow pipes the CLI JSON result into:

```text
collector-result.json
```

and uploads it as a GitHub Actions artifact for 30 days.

This provides durable natural-run evidence while keeping `V06_WRITE_MODE` at
`events_only` and avoiding changes to article-cache or evaluation Sheet schema.

The normal CLI JSON remains visible in the workflow log as well.

## 13. Network and budget safety

PR-7 adds no discovery or extraction requests.

The only request-generating collector remains v0.5.6m, so existing controls stay
single-authority:

- acquisition ceiling: 32 primary attempts;
- Firecrawl daily hard limit: 3;
- existing group reservations unchanged;
- Jina/Direct HTML/Firecrawl fallback decisions unchanged.

The v0.6 shadow runner imports no acquisition client and does not instantiate
`AcquisitionService`.

GitHub's artifact upload is audit persistence, not a collector discovery or
extraction request and cannot consume Firecrawl/Jina budgets.

## 15. Natural holdout rule

PR-7 merge, CI, replay and manual workflow dispatch do **not** count as a natural
shadow day.

Natural Shadow Day 1 begins only with the first scheduled run after the final
PR-7 merge when all of the following are true:

1. control version is `collector-v0.5.6m`;
2. shadow version is `collector-v0.6-pr7`;
3. control final status is success;
4. v0.6 shadow status is success;
5. discovery snapshot is present;
6. shared-body fingerprints close with zero mismatch;
7. shadow request count = 0;
8. shadow Firecrawl request count = 0;
9. shadow incremental cost = 0;
10. artifact is available;
11. code remains frozen after that run begins.

Only scheduled natural runs count toward the required three consecutive days.

## 16. Natural audit procedure

For each qualifying natural run, audit:

### Integrity

- run id / group / scheduled and actual start;
- control and shadow versions;
- full snapshot count;
- control-acquired count;
- shared body count;
- fingerprint mismatches;
- event-chain closure;
- zero-request invariants;
- artifact availability.

### Layer disagreements

- Gate hard rejects, especially those with diagnostic body truth;
- publication disagreements;
- medium/article/transcript disagreements;
- source relationship/action disagreements;
- Editorial verdict disagreements;
- Policy action disagreements;
- control-unacquired Gate-pass items.

### Human quality labels

Only after freezing the run output, manually label the reviewed items and
compute the release metrics defined by the architecture contract:

- hard-reject precision;
- candidate precision;
- serious false accepts;
- actionable recall within attempted items;
- editable final recall;
- selection regret versus legacy.

Do not patch the code from Day 1 and then count the next replay of Day 1 as a
pass.

## 17. Definition of done

PR-7 is complete when:

1. scheduled collection explicitly activates the sidecar in events-only mode;
2. absence of activation flags still chooses legacy-only execution;
3. legacy frozen pipeline files are unchanged;
4. one control discovery run supplies the full shadow discovery snapshot;
5. one control acquisition supplies all shadow body evidence;
6. v0.6 makes zero incremental collector network requests;
7. control attempts are not duplicated into shadow request metrics;
8. Gate diagnostic and effective paths are distinguishable;
9. unacquired URLs never receive fabricated Editorial truth;
10. observed-body Policy/Portfolio runs deterministically;
11. shadow exceptions fail open;
12. primary mode remains forbidden;
13. no Google Sheet schema/write path is added;
14. natural evidence is archived as a GitHub Actions artifact;
15. full repository tests and existing operational CI pass;
16. merge does not itself count as a natural shadow day.
