# v0.6 PR-7.3.5 — Discovery snapshot persistence hardening

## Trigger

The scheduled `intl_early` Natural Shadow run after PR-7.3.3 was:

```text
GitHub workflow run: 31403857908
runtime: collector-v0.6-pr7.3.3
scheduled slot: 2026-08-10 22:30 BJT
shadow discovery snapshot: 143 / 143
capture_gap_count: 0
full_snapshot_invariant: false
```

The collector/shadow execution itself retained the complete in-memory discovery
snapshot. The acceptance failure came from persistence: one serialized
`metadata_json` value exceeded Google Sheets' 50,000-character single-cell
limit, causing the batch append to `collector_discovery_snapshot` to fail.

This is an audit-infrastructure defect rather than a discovery, acquisition, L4,
L5 or L6 semantic defect. A scheduled run cannot count toward Natural Shadow
acceptance unless the complete input snapshot is persistently auditable.

## Scope

PR-7.3.5 is snapshot-persistence-only. It does not change:

- Discovery candidates or prefilter decisions;
- Acquisition behavior or request counts;
- Jina / Firecrawl routing or budgets;
- legacy v0.5.6m control authority;
- PR-7.3.4 L4 page-surface semantics;
- PR-7.3.3 publication/source semantics;
- L5 `editorial-judge-v0.6-pr7.2`;
- L6 policy or portfolio semantics;
- `publication_date_unknown_defer`;
- PR-8/canary state.

The shadow runtime advances to:

```text
collector-v0.6-pr7.3.5
```

and exposes:

```text
snapshot_persistence_version=snapshot-persistence-v0.6-pr7.3.5
```

## Persistence design

The existing `collector_discovery_snapshot` schema remains unchanged.

For normal metadata (<=45,000 characters after compact JSON serialization),
`metadata_json` is written exactly as before.

For oversized metadata:

1. serialize the complete metadata JSON without truncation;
2. compute SHA-256 over the exact UTF-8 payload;
3. split the payload into <=40,000-character chunks;
4. write all chunks to `collector_discovery_snapshot_overflow` using `RAW` input;
5. write a compact manifest to the original `metadata_json` cell containing:
   - persistence version;
   - overflow sheet name;
   - snapshot ID;
   - SHA-256;
   - original character count;
   - chunk count.

Overflow sheet columns are:

```text
snapshot_id
collector_run_id
payload_sha256
payload_chars
chunk_index
chunk_count
metadata_chunk
```

Joining `metadata_chunk` in `chunk_index` order reconstructs the exact original
JSON. The manifest hash provides an integrity check.

## Failure semantics

This patch does **not** turn partial persistence into success.

Overflow chunks are written before the main snapshot rows. If overflow sheet
creation or any chunk append fails, the exception propagates into the existing
recall hook, which records `snapshot_error`. The control result remains preserved,
but `discovery_snapshot_status` remains failed and therefore
`full_snapshot_invariant` cannot pass.

Partial orphan overflow chunks after a failed API call are harmless: they are
uniquely scoped by `collector_run_id + snapshot_id` and are never sufficient to
claim a successful main snapshot.

## Regression coverage

Tests cover:

- small metadata remains inline and does not create an overflow sheet;
- >50k metadata is losslessly chunked;
- reconstructed JSON equals the exact original serialization;
- SHA-256 matches after reconstruction;
- every chunk stays below the safe cell threshold;
- overflow write failure propagates rather than being silently truncated;
- the main snapshot row is not written if overflow persistence fails first;
- runtime and persistence version markers are explicit.

## Acceptance semantics

CI proves the persistence logic, but does not increment Natural Shadow acceptance.
Natural Shadow remains **Day 0** after this PR is merged.

The next scheduled post-merge run can become the next Day 1 candidate only if it
shows, at minimum:

```text
pipeline_version = collector-v0.6-pr7.3.5
snapshot_persistence_version = snapshot-persistence-v0.6-pr7.3.5
full_snapshot_invariant = true
capture_gap_count = 0
shadow_request_count = 0
shadow_firecrawl_request_count = 0
shadow_incremental_cost = 0
body_fingerprint_mismatches = 0
```

Semantic acceptance must then be evaluated independently as before.
