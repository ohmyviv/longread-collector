# Longread Collector v0.6 PR-4: Policy & Portfolio Selector

Status: deterministic development implementation  
Baseline: `main@b7214fc9` (`v0.6 PR-3`)  
Legacy control: `collector-v0.5.6m`  
Production integration: none

## 1. Purpose

PR-4 implements the L6 **Policy & Portfolio Selection** layer.

The selector answers:

> Given Canonical Article facts and an Editorial Assessment, what action should
> the daily policy take, and which eligible items should occupy limited
> portfolio slots?

PR-4 is the first v0.6 layer allowed to emit policy actions:

- `select_standard`;
- `select_special`;
- `source_chase`;
- `defer`;
- `reject`.

It still does **not** write legacy compatibility fields such as
`formal_candidate`, `special_candidate`, `eligible_for_editor` or
`reject_reason`. Those remain the responsibility of a future FinalProjector.

## 2. Inputs and outputs

Per-item inputs:

- immutable `CanonicalArticle`;
- immutable `EditorialAssessment`;
- optional estimated acquisition cost.

Portfolio input:

- a sequence of immutable `SelectionCandidate` objects.

Output:

- immutable `SelectionDecision` for every input item;
- immutable `PortfolioSelectionResult` containing selected ids, source-chase ids
  and total marginal utility.

## 3. Policy action precedence

PR-4 deliberately keeps intrinsic editorial failure separate from source chase.

Order:

1. insufficient evidence + canonical source action -> `source_chase`;
2. insufficient evidence without chase path -> `defer`;
3. editorial reject or dominant risk -> `reject`;
4. low editorial value -> final policy `reject` when confidence is adequate,
   otherwise `defer`;
5. actionable content requiring a better/original source -> `source_chase`;
6. original/usable actionable content -> standard or special selection track.

This matters for television transcripts. A CCTV transcript that is intrinsically
excluded remains `reject` even if Canonical Article knows an original-source URL.
Chasing the original does not turn a television program transcript into an
independent longread.

Conversely, a substantive PBOC document carried by a secondary host can emit
`source_chase` to obtain the primary document. Source chase is a workflow action,
not a quality rejection.

## 4. Selection tracks

### Standard longread

Used for ordinary media articles, reported features, interviews, analysis,
commentary and book reviews that remain actionable after the Editorial Judge.

### Special document

Used for primary documents and equivalent special materials once the canonical
source is already suitable for display.

### Academic

Used for academic papers. Academic material is not punished for lacking
journalistic original-reporting signals and receives a smaller freshness
penalty.

### Source chase

Used when Canonical Article identifies that a better/original source must be
obtained before final selection.

## 5. Expected editorial utility

PR-4 reconstructs a selection utility from the PR-3 dimensions.

Standard longreads weight:

- substance;
- original reporting;
- analysis;
- argument;
- evidence density;
- reader value;
- timeliness relevance.

Special/academic tracks shift weight away from journalistic reporting and toward
substance, analysis and evidence.

The selector then subtracts independent penalties for:

- promotional/event/transcript/template risk;
- freshness;
- optional expected acquisition cost;
- source concentration;
- genre concentration;
- duplicate clusters.

Costs are intentionally light-weight in PR-4. PR-5 will own the authoritative
acquisition budget ledger.

## 6. Portfolio semantics

A strong article that loses a slot because the daily portfolio is full is:

`defer`

not:

`reject`.

Likewise, an item suppressed because the same duplicate cluster is already
selected is deferred with an explicit redundancy reason.

This preserves the distinction between content quality and portfolio capacity.

The selector uses greedy marginal utility. On each step it recomputes source and
genre concentration penalties against the already selected portfolio.

The implementation is deterministic and stable-tied by `item_id`.

## 7. Source diversity and redundancy

Source concentration is a soft penalty rather than a hard site quota.

The initial development calibration adds:

- a progressive same-source penalty;
- an additional penalty after a configurable soft source cap;
- a small repeated-genre penalty.

Exact duplicate-cluster reuse receives a near-terminal redundancy penalty, so
the same content cluster cannot occupy multiple portfolio slots.

These rules are policy choices rather than Canonical facts.

## 8. 24+4+4 shadow acquisition planner

PR-4 also introduces a **shadow-only planning interface**:

- 24 exploitation forecasts;
- 4 dynamic replacement reserves;
- 4 stratified exploration forecasts.

The planner consumes `AcquisitionForecast` objects supplied by a future
integration layer. PR-4 does not generate those forecasts from production
Discovery data and does not perform network requests.

Exploit ranking combines expected editorial utility, confidence and expected
cost with a small source concentration penalty.

Replacement reserves are the next highest expected-value candidates.

Exploration favors:

- forecast uncertainty;
- underrepresented strata;
- underrepresented sources;
- non-zero expected editorial value.

A deterministic legacy 24+8 comparator is included for offline replay.

The 32-attempt ceiling remains unchanged.

## 9. Development replay

The fixed PR-4 replay reuses the PR-3 human-label fixture derived from:

- audit `SHADOW-AUDIT-20260806-2018-BJT-V056M-ZHEVENING-FULL32`;
- run `COL-20260806-195235-BJT-zh_evening`.

A small PR-4 policy fixture records the historically observed legacy action and
the expected v0.6 policy action for the reviewed cases.

Important expected transitions include:

- two complete Turnintl articles: legacy reject -> `select_standard`;
- CCTV transcript: legacy formal candidate -> `reject`;
- Shanghai Book Fair preview: legacy formal candidate -> `reject`;
- ideological commentary: legacy formal candidate -> policy `reject` after PR-3
  correctly labels it `LOW_VALUE`;
- PBOC secondary-host document: legacy ordinary candidate -> `source_chase`;
- external PeopleApp shell: legacy reject -> `source_chase`;
- academic paper -> `select_special / academic`.

The development test requires weighted action regret to improve by at least 80%
versus those fixed legacy labels.

This is a **development/golden replay**, not a natural holdout or release claim.

## 10. Counterfactual planner replay

A separate synthetic counterfactual checks the 24+4+4 planning algorithm.

The replay contains:

- 28 obvious high-value items;
- 4 uncertain high-value items in an underexplored stratum;
- 8 high-legacy-priority low-value template traps.

The 24+4+4 planner uses exploration to recover the four hidden strong items,
while the static 24+8 comparator consumes four trap slots.

This test verifies algorithm behavior only. It does not count toward the
three-natural-day release gate.

## 11. Evidence and auditability

Every `SelectionDecision` emits selection-stage evidence for:

- policy action;
- selection track;
- marginal utility;
- risk penalty;
- diversity penalty;
- freshness penalty;
- cost penalty.

All evidence uses `StageName.SELECTION`.

Canonical and Editorial inputs remain immutable.

## 12. Production safety boundary

PR-4 changes no active production behavior:

- no legacy `pipeline*` edits;
- no production classification edits;
- no active selector integration;
- no runtime-config or Sheet writes;
- no new discovery or extraction requests;
- no Firecrawl changes;
- no change to the 32-attempt ceiling;
- no 07:35 editor connection;
- no automatic promotion.

`DEFAULT_V06_MANIFEST` advances only to:

- `architecture_version = collector-v0.6-pr4`;
- `migration_phase = pr4_policy_portfolio`.

All production-safety booleans remain `False`.

## 13. Definition of done

PR-4 is complete when:

1. all five policy actions are reachable and semantically separated;
2. source chase never masquerades as editorial reject;
3. intrinsic editorial reject can take precedence over unnecessary source chase;
4. primary documents and academic papers use separate tracks;
5. capacity loss and duplicate suppression produce `defer`, not quality reject;
6. portfolio decisions carry explicit utility and penalty evidence;
7. shadow planning never exceeds 32 attempts;
8. the planner produces 24+4+4 when enough eligible forecasts exist;
9. hard-reject forecasts never enter the plan;
10. the fixed development replay reduces weighted legacy action regret by at
    least 80%;
11. existing repository tests pass;
12. no active legacy or production file changes.
