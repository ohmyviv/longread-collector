# v0.6 PR-2: Canonical Article layer

Status: implementation contract  
Legacy control: `collector-v0.5.6m`  
Runtime integration: none  
Production behavior: unchanged

## 1. Purpose

PR-2 is the first v0.6 layer that produces new factual semantics rather than
only projecting legacy state. It resolves a fetched page into a
`CanonicalArticle` before editorial scoring or portfolio policy.

It answers:

- what page surface is being viewed;
- what the main content medium is;
- what structural editorial genre the content has;
- what publication evidence is strongest;
- who hosts the page and who produced the content;
- whether the current page is original or a republication;
- whether the next action is to retain the page or pursue an original source.

It does **not** answer whether the daily editor should select the content.

## 2. Production evidence used for fixed replay

The fixture `tests/fixtures/v06_canonical_day1.json` is derived from the
2026-08-06 `zh_evening` natural run and its human review. It preserves only the
minimum body snippets, metrics and metadata needed to reproduce the canonical
facts; it does not contain a title whitelist.

The replay covers:

1. three substantive 转角国际 articles with 11-13 embedded video artifacts;
2. a CCTV `焦点访谈` program transcript with a long text body;
3. a ThePaper shell pointing to a PeopleApp original;
4. a Bank of China page transparently republishing 21世纪经济报道;
5. a Guangdong finance-office page republishing a PBOC primary document;
6. a directly hosted government planning document.

## 3. Separation of dimensions

### Page surface

`page_surface` describes the web shell:

- `article_page`
- `document_page`
- `external_link_stub`
- other values already defined by the PR-0 contract

### Main content medium

`main_content_medium` describes what the substantive payload is:

- `written_article`
- `primary_document`
- `television_transcript`
- `video_page`
- `unknown`

An embedded video count is evidence only. It never directly forces
`video_page`.

### Editorial genre

`editorial_genre` describes structure:

- interview titles become `interview`;
- primary documents become `policy_document`;
- clearly conceptual multi-section pieces become `analysis`;
- other substantial narratives become `reported_feature`.

A later Editorial Judge may decide that a transcript or feature has low daily
value; PR-2 does not.

## 4. Medium rules

A television transcript requires several independent broadcast signals, such as:

- a broadcast-outlet message line;
- a named-program parenthetical;
- player controls or duration;
- a program title prefix;
- an embedded video.

By contrast, a page with >=1500 substantive prose characters is treated as a
written article when broadcast-transcript evidence is absent. Therefore a long
article may contain many embedded videos and still remain a written article.

`video_page` is reserved for pages where video is present and substantial
written prose is absent.

## 5. External-link shells

A page is an `external_link_stub` only when:

- it exposes an external target on a different host; and
- the local substantive prose is negligible.

The canonical action becomes `replace_with_original`; the item is not encoded
as an editorial rejection.

When the fetched body already contains the full external article, the page is
not a stub. It can still have `secondary_republish` relationship and
`replace_with_original` action.

## 6. Source resolution

The layer separately resolves:

- `hosting_source`
- `canonical_source`
- `original_publisher`
- `source_relationship`
- `source_action`

Evidence priority includes:

1. explicit body source labels;
2. known external original targets;
3. document issuer inferred from a primary-document title;
4. hosting-source metadata and official copyright/organizer information.

A complete media republication may be retained at the current display URL.
A republished primary government document without a resolved original URL emits
`find_primary_document`.

## 7. Title resolution

A substantive body heading may replace the raw page title when:

- the raw title is absent;
- title similarity is low; or
- the raw title looks like an institution/site title.

This fixes host-site titles without source-specific title exceptions.

## 8. Publication resolution

PR-2 treats dates as factual evidence only. It prefers:

1. high-confidence body publication evidence;
2. previously resolved factual publication metadata;
3. acquisition raw dates;
4. discovery date hints;
5. labeled dates parsed from the body.

No age window or freshness rejection is applied in the Canonical layer.

## 9. Invariants

PR-2 maintains all migration safety boundaries:

- no active pipeline integration;
- no runtime-config integration;
- no Sheet writes;
- no new network requests;
- no change to the 32-attempt cap;
- no Firecrawl budget change;
- no 07:35 editor connection;
- no automatic promotion.

The root `import longread_collector.v06` remains free of legacy pipeline
side effects. Canonical resolution operates only on v0.6 immutable contracts.

## 10. PR-2 definition of done

PR-2 passes when:

- all eight production-derived replay cases resolve the intended factual
  canonical state;
- 11-13 embedded videos do not override a substantive written body;
- a long CCTV program transcript remains a transcript;
- an external-link shell emits source chase rather than a rejection semantic;
- transparent media republication resolves its media publisher;
- republished primary documents resolve the issuing authority;
- a low-similarity host title is replaced by the article body heading;
- primary-document publication date evidence remains factual and policy-free;
- inputs remain immutable;
- the full repository test suite passes;
- no active production file changes.
